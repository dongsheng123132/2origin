# Paper 方言 —— 用本象表示「一批论文的主张，以及我们凭什么信它」

读论文的默认产物是**散文摘要**。散文有三个结构性缺陷：

1. **读没读过原文，散文里看不出来** —— 同一句话可能来自 abs 页，也可能来自搜索引擎的二次转述
2. **数字与它的成立条件分家** —— 「+16.6 点」脱离基准、脱离预算就是个装饰
3. **作者自称与外部复现混在一起** —— 论文里的「我们提升了 X」是作者给自己发证

这个方言把三件事变成会变红的判据，而不是写作纪律。

## 五类对象

| 类型 | 是什么 | 关键约束 |
|---|---|---|
| `paper:` | 论文本身 | 元数据必须来自外部索引；必须声明读到什么程度、成熟度 |
| `claim:` | 论文做的一条主张 | **按定义是作者自称，一律 `candidate`** |
| `repl:` | 独立复现 | 唯一能把主张抬成 `verified` 的东西，且必须独立于原作者 |
| `bench:` | 评测基准 | 必须交代是否公开可跑 |
| `critique:` | 论文之间的批评关系 | 批评是否被回应，是领域可信度的一手指标 |

`claim:` 与 `repl:` 是**两个命名空间，不是一个字段的两个取值**。这是刻意的：
作者自称的主张，无论写得多确定，都进不了 `repl:`。
**用命名空间承载举证责任，比用字段更难绕过。**

## 三格最值钱的字段

- **`read_level`** —— `fulltext` / `abstract` 合法，`search_snippet`（只见搜索引擎转述）**判红**。
  把它写成 `abstract` 来换绿灯，是这套方言唯一真正防不住的作弊，也是唯一不可原谅的。
- **`budget_reported`** —— 报增益必须同时报搜索/推理预算。判据直接来自
  [arXiv:2607.12227](https://arxiv.org/abs/2607.12227)：harness evolution 自己就是一次迭代搜索，
  不报预算就分不清收益来自设计还是来自算力。
- **`maturity`** —— `peer_reviewed` / `preprint` 合法，`outline`（占坑稿）与 `release`（软件发布物）判红。
  **这一格是跑真数据跑出来的**：第一版没有，直到录进一条正文自述
  「structured research outline establishing priority, full paper in preparation」的 Zenodo 存档——
  那是占坑不是论文，但它当时和完整预印本长得一模一样，主张会被同等计入结论。

## 没有一行新的校验代码

全部落在 `compiler/constraints.mjs` 既有的谓词上：`exists` / `in` / `equals` / `unique` / `count`。
**若表示一批论文还需要改校验器，那它就不是协议，只是又一个文献管理器。**

## 跑

```bash
node adapters/paper/selftest.mjs      # 29 条，多数是反向用例
```

真实用例见 ShadowOS 仓库 `demo/harness-lit/`：18 篇 harness 论文过这套判据，
结果是 **0 条独立复现、22 条主张全部停在 candidate**，
且**报增益的 9 条主张里报了预算的 0 条**。

## 一条必须一起打印的话

判据集在**空包**上必然全绿。所以调用方**必须同时打印录入条数**——
否则「0 违规」会被读成「都核过了」，那就是恒绿考题。
