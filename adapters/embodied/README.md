# Embodied 方言 · 机器人语义世界状态 v0.1

这不是一套新的 SLAM、场景图或机器人中间件。它是本象协议中的一个新方言：接收上游感知已经识别出的少量**语义事件**，保存可审计的事件真源，再用确定性 reducer 生成机器人在某一时刻可使用的 `current_belief`。

## 边界

| 层 | 负责什么 | 是否进入 `.origin` / 本方言 |
|---|---|---|
| 相机、VLM、检测器、跟踪器 | 像素转检测与 track | 否，只引用来源指纹和时间区间 |
| SLAM / tf2 / 几何场景图 | 位姿、坐标系、点云、占据栅格 | 否，保持行业原生表示 |
| Embodied 方言 | 持久对象、关系变化、事实/推断/未知、证据、时间 | 是 |
| MoveIt / PLC / 安全控制器 | 规划、执行、急停与实时闭环 | 否；本方言不能成为安全回路 |

因此当前选择是：**在本象协议内新增 `embodied` 方言，不改通用核心，也不另造一套机器人平台。**

## 五个概念怎么落地

- 对象：`A`、`B` 这类持久 object ID；感知 `track_id` 只是别名，不能冒充对象身份。
- 引用：`source_id + sha256 + interval_s`，指向传感器原片中的证据区间，不复制视频。
- 投影：`last_observation` 和 `current_belief`。前者回答“最后看见什么”，后者回答“现在有资格相信什么”。
- 事务：一条 append-only observation event，例如 `object_observed`、`track_lost`、`put_inside`。
- 校验：提交/回放前检查对象引用、负载、证据指纹、证据区间和三种时间；任一错误则整次 fail-closed。

## 三种时间

- `valid_from`：所描述的现实变化从何时开始成立。
- `observed_at`：机器人何时获得这条观察；在这之前不能进入知识投影。
- `committed_at`：事件何时被追加到状态包，用于审计提交顺序。

证据区间必须在 `observed_at` 时已经完整可用，不能延伸到未来；持续可见需要后续观察事件刷新。

把三者混成一个时间会产生严重的“未来信息泄漏”：例如物体 19 秒开始移动、26 秒才确认到达 R，则 25 秒的知识投影不能提前声称它在 R。

## v0.1 的确定性规则

1. 普通静态遮挡不自动否定最后位置；证据区间结束后，该位置从 `observed` 降为 `inferred`。
2. 若物体先被手接触再遮挡，旧位置被显式作废为 `unknown`，直到重新观察。
3. `track_lost` 作废当前位置；相似外观的新 track 不自动继承旧对象 ID。
4. `inside(B,A)` 成立时，B 的全局位置从 A 的当前位置派生，状态始终是 `inferred`。
5. 新的直接观察覆盖旧的作废记录，但不会删除事件历史。

## 运行

```bash
node adapters/embodied/selftest.mjs
node adapters/embodied/replay.mjs adapters/embodied/fixtures/pilot-events.json S02-hidden-move 11
```

## 当前证据与诚实边界

`fixtures/pilot-events.json` 把首轮四组视频实验人工转成了语义事件，用于验证状态语义与门禁；它**没有**证明任一视觉模型能稳定自动产生这些事件。首轮 benchmark 也没有证明本象能提升视觉问答准确率，只有“确定性 reducer 能阻止几类已知状态错误”这一较窄结论。

v0.1 还没有处理概率分布、多机器人合并、乱序迟到事件、对象 ID 合并/拆分、撤销、更复杂的空间拓扑和实时资源上限。它也不是“行业最佳方案”的证据；更合适的工程定位是 ROS 2 / tf2 / SLAM / 场景图之上的**可审计语义状态层**。
