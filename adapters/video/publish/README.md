# 投放清单 · 把断言变成 measured

**这不是"发三条视频"，是一次有预注册预测的实验。**

现在两份 timeline 的估值 **100% 是 asserted**（模型的判断），没有一条 `measured`。
这是整个体系的天花板：所有相关性检验（话密度 ρ=0.568、韵律 ρ≈0.1）量的都是
「和我的判断一致」，不是「客观有效」。**一次真实反馈能同时解开这三件事。**

## 二、预注册预测（发之前写死，发完不许改）

> **P1** A 版（钩子在前）前 3 秒留存 **高于** B 版。
> 依据：`L03` 在 live-clip 受众下 hook 档 = 5，`L09` hook 档 = 5，但 L03 的 payoff 也是 5。
> **证伪条件**：B 版前 3 秒留存 ≥ A 版，则「35倍价差是最好的钩子」这条断言被推翻。
>
> **P2** 两版在 **L11 段（为AI优化）** 的相对留住都排进前二。
> 依据：L11 是唯一一个三个维度全 5 档的事件（value=1.0）。
> **证伪条件**：L11 段流失速率高于全片平均，则最高分那条断言最不可信。
>
> **P3** 开发者版的完播率显著高于抖音版。
> 依据：受众定义里写了「愿意看完 5 分钟」。
> **证伪条件**：完播率相近或更低，则 `dev-2026H2` 这个受众画像是我编的。
>
> **P4（最可能被推翻的一条）** 我预计 P1–P3 里**至少有一条会挂**。
> 四轮下来我在代理变量上错了三次（响度、活跃度、语速），没有理由认为这次一次不错。

## 三、要收的数据

**只要一样东西：逐秒留存曲线。**

- 抖音：创作者中心 → 作品数据 → 「完播率/观众留存」曲线，逐秒
- 视频号 / B站：后台同名指标
- 拿不到导出就**照着曲线读点**，每 2–3 秒一个点，5 个点以上就能算

存成 CSV：

```csv
second,pct
0,100
1,96.2
2,91.5
...
```

**顺带记下但本次不入库的**：点赞、评论、下单。转化和留存是两个目标，
`ingest.mjs` 只处理留存，别把它们混在一起。

## 四、拿回来怎么入库

```bash
cd lab
node ingest.mjs n2/timeline.origin.json \
     --projection douyin_60s --retention ../publish/douyin_a.csv --write
```

它会做四件事：

1. 把输出时间映射回源时间码（按投影的 pick 顺序）
2. 用**相对流失速率**算每段的「留住能力」——不是绝对留存
3. 追加 `basis: measured` 的估值，**旧断言不删**（A5：可对比记录）
4. 报出哪几条与我的断言偏差 >0.25 —— **那就是我错的地方**

之后 `validate.mjs` 会自动以 `measured` 为准，assertion-ratio 第一次会低于 100%。

## 五、这个实验自己的边界（A6：留存也是代理）

留存率不等于内容价值。已知三条失效域，全部写进 `ingest.mjs` 产出的 limits：

1. **位置效应压倒内容** —— 留存曲线单调递减，第一段永远最高。
   所以用相对流失速率而非绝对留存。**校正不完美**，A/B 换序正是为了绕开这一条。
2. **结尾 CTA 留存必然低，而那是唯一转化点。** 留存低 ≠ 没价值。
3. **前 2 秒受平台强制曝光影响**，已默认丢弃（`--skip-head 2`）。

此外：单次投放无法区分内容效应与账号权重、发布时段、推荐随机性。
**样本不足时只看方向，不看数值**（`M-AB-SINGLE-FACTOR`）。
