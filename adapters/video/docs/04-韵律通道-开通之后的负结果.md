# 04 · 韵律通道：开通之后，我要的那两个字段没用

**Status:** 实验记录 · 含负结果
**Date:** 2026-08-09
**前提：** [03](03-语音通道-阻塞点解除.md) 说腾讯云带 `EmotionRecognition` / `SpeakerDiarization`，
是「离自动找爆点最近的一步」，账号未开通。**用户去控制台开通了。**

---

## 〇、结论先行

开通生效，通道跑通了。**但我指望的那两个字段（语速、情绪能量）与价值判断无关。**
真正有用的是一个我一直没注意的、任何 ASR 都能算出来的指标：**话密度（字/秒）**。

## 一、通道本身：可用

```
node tc-asr.mjs n2/live.mp4 --chunk 300
1663s → 6 块 × 300s → 24.6 秒跑完
493 段 / 4190 字 / 语音占 45% / 说话人 1 个
```

`CreateRecTask` 的 `ResultDetail` 每句带四个**跟语义单元对齐**的测量值：

| 字段 | 实测值域 |
|---|---|
| `SpeechSpeed` | 语速，中位 5.1 字/秒 |
| `EmotionalEnergy` | 情绪能量，中位 4.62 |
| `SilenceTime` | 句前停顿，0–数千 ms |
| `SpeakerId` | 说话人 |
| `EmotionType` | **全空，0 条** |

分类情绪（`EmotionType`）一条都没出来。只有 `EmotionalEnergy` 这个数值。

## 二、相关性检验：我要的字段没用

`tc-asr.json` 自带的 `T-PROSODY-NOT-VALUE` 要求先测再用——因为本项目
[已经栽过一次](01-粗筛层-一个被推翻的方案.md)：10s 窗的 RMS 峰值与价值**反相关**。

n=19 事件，Spearman 秩相关：

```
指标              ρ        判定
语速均值          0.288    无关
语速峰值          0.084    无关
情绪能量均值       0.233    无关
情绪能量峰值       0.065    无关
最长停顿         -0.535    弱负相关
话密度(字/秒)     0.568    弱正相关   ← 最强
```

取各指标 top3 落在哪些事件上，比 ρ 更直观：

```
语速均值    L14(v=0.28) L19(v=0.10) L11(v=0.95)   ← 前两名是最该删的段
情绪能量峰值 L17(v=0.72) L08(v=0.55) L09(v=0.90)   ← 还行，但 ρ 只有 0.065
话密度      L03(v=0.92) L12(v=0.75) L04(v=0.66)   ← 三个都是好料
```

**语速快的地方不是爆点，是他在赶话或者念叨。** 情绪能量峰值虽然 top3 还行，
但整体 ρ=0.065，等于没有信号。

**最长停顿 ρ=−0.535** 说得通：长停顿 = 在干活不说话 = 信息稀疏。它其实就是话密度的倒影。

## 三、有用的那个指标，不需要腾讯

`话密度 = 该区间的转写字数 / 区间墙钟时长`（含静默）。

它只需要**文本 + 时间戳**，任何 ASR 都给。为它开通的腾讯韵律字段，一个都没用上。

拿它重做第一轮失败的粗筛（30s 窗，按话密度排序取 top-K）：

| 预算 | 保留 | 加权召回 | 随机基线 | 增益 | 误纳负面素材(≤0.3) |
|---|---|---|---|---|---|
| 41% | 690s | 54.2% | 41.5% | **+31%** | 13.0% |
| 30% | 510s | 42.5% | 30.7% | **+38%** | 11.8% |
| 20% | 330s | 30.5% | 19.8% | **+54%** | **0.0%** |

对照 [01](01-粗筛层-一个被推翻的方案.md) 的声学粗筛：33.4% vs 随机 40.7%，增益 **−18%**。

**所以第一轮粗筛失败不是方法错，是信号选错了。**
「一段素材里单位时间说了多少字」是内容密度的直接度量；
「一段素材有多响、镜头切了几次」是拍摄行为的度量，跟内容无关。
前者是对象，后者是影子——又一次同样的错。

20% 预算下误纳负面素材降到 0%，说明它能把「在干活/闲聊/掉线」这类低信息段稳定排到后面。

## 四、这不取代两遍制

两遍制粗读的召回是 **99.3%**（因为它不丢东西，只降分辨率）。话密度粗筛是 54.2%。
两者不是竞争关系：

- **两遍制** 决定「怎么看完全部素材」——默认路径
- **话密度** 决定「二遍精读的钱花在哪」，以及素材长到连粗读都吃不消时怎么先砍一刀

## 五、诚实边界

- **n=19 事件，一条素材，参照是 asserted。** 量的是「话密度与我的判断是否一致」，
  不是「话密度客观有效」（bugscope A2）。ρ=0.568 是弱相关，不是定律。
- **话密度必然偏爱"讲课"、歧视"演示"。** 一个安静地把海报全屏展示 5 秒的镜头
  （素材1 的 e10b，value 0.98）话密度会很低。**对以画面为主的素材，这个指标会系统性判错。**
  素材2 是纯口播直播，正好是它的最佳场景。
- **`EmotionType` 全空的原因没查清。** 可能是引擎型号（`16k_zh`）不支持、
  可能是该素材确实没有强情绪。没有排查就不能说「腾讯的情绪识别没用」，
  只能说「本次配置下没拿到」。
- **分块切句。** 6 块按固定 300s 切，切点落在句中时那句被拆成两条不完整记录，
  语速与情绪能量随之失真。受影响位置已写进 `T-CHUNK-CUTS-SENTENCES`。
- **两条 ASR 的转写不一致。** 百炼「优质一点」，腾讯「荧光点」；百炼「能说」，腾讯「李说」。
  两条都可能错。

## 六、那开通腾讯白开了吗

没有，但收益不是我说的那个：

- ✅ **说话人分离**（`SpeakerId`）——这条直播只有 1 个说话人所以看不出价值，
  连麦/对谈/多人会议素材上是刚需，百炼那条也有 `--diarization` 但没测过
- ✅ **更细的分段**（493 段 vs 百炼 294 段），做句边界吸附时更准
- ❌ 语速、情绪能量：本次实测无用
- ❓ 分类情绪：没拿到，原因未查

**而真正解决问题的话密度，两条通道都能算。**
