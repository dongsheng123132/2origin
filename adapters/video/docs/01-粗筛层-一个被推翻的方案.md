# 01 · 粗筛层：一个被推翻的方案，和替代它的那个

**Status:** 实验记录 · 含撤回主张
**Date:** 2026-08-09
**被推翻的：** 声学 / 场景粗筛（`lab/triage.mjs`）
**替代它的：** 两遍制粗读—精读（`lab/sheet.mjs`）

> 本页仿 本象协议 research 里 Run #18 / #27 的做法：**撤回自己已经发布的主张，并留下原件。**
> `triage.mjs` 不删，它是这条负结果的可复核证据。

## 〇、要解决的问题

100 小时素材 = 360,000 秒。按上一版 5s 抽帧、20 格/张，需要 **3,600 张联系表**，VLM 读不起。
这是唯一挡在真实场景前面的东西。

## 一、方案 A（我先做的那个）：声学 / 场景粗筛

思路：用纯 ffmpeg 的确定性信号给素材排序，只把预算内的窗口送去精读。

信号（全部 `basis: measured`，可复算）：镜头切换、逐秒 RMS 响度、静音区间、黑场 / 静止画面。
排序权重（`basis: asserted`，手工拍的）：语音 .40 / 响度 .25 / 切换 .20 / 停顿节奏 .15。

跑 295 秒实测：30 个 10s 窗，预算 12 → 保留 120s（41%），丢弃 175s。

### 结果：跑输随机基线

```
价值加权召回: 33.4%   （随机抽同样时长的期望 ≈ 40.7%）
候选精确率:   25.0% 的候选秒数落在高价值事件(≥0.7)上
误纳负面素材: 37.5% 的候选秒数落在必须剔除的低价值事件(≤0.3)上

✗ e02  12–26s value=0.92  覆盖 0%    ← 全片最强的产品承诺，整段丢掉
✗ e10 200–224s value=0.95 覆盖 17%   ← 全片唯一的视觉爆点，只剩一角
✓ e05  75–100s value=0.25 覆盖 100%  ← 『一个没装上』的失败画面，完整保留
✓ e08 170–180s value=0.05 覆盖 100%  ← 镜头扫到房间的穿帮，完整保留
```

复核：`node lab/recall.mjs`（退出码 1）

### 根因（可复算）

```
speech   取值集合: 0.400            ← 常数
rhythm   取值集合: 0.000            ← 常数
cut      取值集合: 0.200 0.000 0.100
energy   取值集合: 0.159 … 0.250
```

- `silencedetect` 在 -32dB 下测到 **0 段静音**——连续讲解本来就不停顿。
  于是 `speech_ratio` 全片恒为 1，`pause_count` 恒为 0，**55% 的权重是死的**。
- 实际起作用的只剩「最响 + 手最抖」。而这两个在本类素材上**与价值反相关**：
  最响的窗口（+9.7dB）是 e05「一个没装上」，切换最多的是 e08 镜头扫到房间的穿帮。

这不是调权重能救的。`triage.json` 里那条 `T-NO-SEMANTICS` 事先写对了：

> 一段安静的、无镜头切换的、音量平稳的画面，若恰好是全片最关键的一句话，本层必然把它排到末尾。

e02 就是这样被丢掉的。**边界写对了，我还是先做了这个方案**——第七要素降低"不知道自己不知道"，
消灭不了"知道了还往坑里跳"。

## 二、方案 B（替代方案）：两遍制粗读—精读

**关键转向：成本的杠杆不是「看哪些窗口」，是「看得多细」。**

方案 A 的病根在于它**盲丢**素材——丢掉的 175 秒没有任何人看过一眼，
而它无法说出自己丢了什么（bugscope A4）。方案 B 不丢任何东西，只降低时间分辨率：

```
一遍  粗读：整条素材，15s 抽帧，48 格/张  → 100% 时长覆盖，时间分辨率 15s
二遍  精读：只对 value≥0.7 的区间，1.5–2s 抽帧 → 边界与爆点定位
```

### 实测

一遍：295 秒 → **1 张联系表**，13 个事件里命中 12 个。

```
价值加权召回: 99.3%   覆盖时长: 100%（无盲丢）
唯一漏掉: e08 (170–180s, value=0.05)  ← 10s 事件掉进 15s 格缝
```

限制的形状变了，这是最重要的一点：从「175 秒没人看过」变成「短于 15 秒的事件可能掉进格缝」——
**后者可量化、可用二遍补，前者不可知。**

二遍在三个高价值区间上都改写了结论：

| 事件 | 一遍（15s）的结论 | 二遍（1.5–2s）看到的 | 影响 |
|---|---|---|---|
| e10 | 200–224s 是一个 value 0.95 的「视觉高潮」 | 200–216 只是铺垫（图在小窗口里，0.62）；**216–226 才是爆点**：海报全屏铺满 + 作者脱口而出「真的是已经非常好了」（0.98） | 抖音版第 2 段从 `[204,216]` 改成 `[216,226]`，**原来剪的是铺垫不是爆点** |
| e02 | 12–26s 一整段 value 0.92 | 真正的钩子是 14.5s 那句「**点这个一键全安装**」——UI 上就有那个按钮，画面与口播同时坐实承诺；20–26s 是含糊重复 | 拆成 e02 / e02b / e02c，抖音版取 `[13.5,20]+[26,29.5]` |
| e13 | 275–295s 一整段 value 0.85 | **286s 有一段镜头晃动的糊帧**，原 pick `[283,291]` 正压在上面；287s 之后手机支付页才稳定清晰 | 拆成 e13 / e13b，抖音版改取 `[287,294]` |

三处里有两处是**原来的剪辑点是错的**，一遍粗读根本看不出来。

### 成本

| 方案 | 100 小时需要的联系表 | 加权召回 | 盲丢 |
|---|---|---|---|
| 原始（5s / 20 格） | 3,600 张 | — | 无 |
| 方案 A 声学粗筛 | 1,464 张 | **33.4%（低于随机）** | 59% 素材 |
| **方案 B 一遍粗读**（15s / 48 格 @200px） | **500 张** | **99.3%** | **0** |
| 方案 B 二遍精读 | 只对高价值区间，通常 <5% 时长 | — | 0 |

**方案 B 比原始便宜 7.2 倍，比失败的方案 A 还便宜 3 倍，而且不盲丢。**

48 格 / 200px 的可读性已实测：`lab/sheets_dense/sheet_01.jpg`，烧录字幕仍可读出
（格 2「点这个一键全安装」、格 19「最重要的是看这个AI学院」、格 47「充值才能激活」）。

## 三、顺带修掉的一个结构性 bug

上一版把时间戳烧进画面：`drawtext=text='%{eif\:trunc(t*5)\:d}s'`。
那个 `t*5` 是**第二个时间公式**，和驱动抽帧的 `fps=1/5` 各算各的，一旦不一致，
产出的联系表看起来完全正常，下游写出的所有时间码全错，而管线一声不吭。

`sheet.mjs` 的修法不是加检查，是**让第二份公式不存在**：画面里只烧格号 `%{n}`（帧计数器，
不是时间公式），格号→时间的映射只存在于 manifest 里，由驱动抽帧的同一个 `stride` 常量算出。
**一个公式，一个真源**（引用优先 §1：不去跟漂移斗争，而是结构上让漂移不可能发生）。

## 四、把边界的 remedy 变成可执行检查

`V-PASS1-RESOLUTION` 的 remedy 是「对 value≥0.7 的事件一律跑二遍精读」。
`validate.mjs` 现在直接查这一条：

```
⚠ [hi-value-not-refined] 1 个高价值事件（≥0.7）只经过一遍 15s 粗读，未做二遍精读：e03
   —— 它们的边界和爆点位置可能像 e10 一样是错的
```

边界不再只是包里的一段声明，而是一条会盯着你的待办。

## 五、诚实边界

- **n=1。** 全部结论来自一条 295 秒的录屏讲解素材。直播、实拍、多机位、无字幕素材
  上的行为**完全没测过**。
- **参照是 asserted 的。** `recall.mjs` 用的是同一个模型早先打的分，是「用自己的判断
  检验自己的筛子」（bugscope A2）。它能发现"筛子和我不一致"，发现不了"我们俩一起错了"。
  **方案 A 的 33.4% 这个数字，量的是"与我的判断不符"，不是"客观上差"。**
  ——但方案 A 把「一个没装上」的失败画面 100% 留下、把最强卖点 100% 丢掉，
  这两条不需要判据也站得住。
- **方案 B 的 99.3% 同样是对着自己的参照量的**，且参照本身就是用 5s 抽帧读出来的，
  与一遍粗读同源。它证明的是"15s 粒度不比 5s 粒度丢事件"，不是"这份 timeline 是对的"。
- **48 格 / 200px 的可读性只在这一种素材上验过**：手机翻拍的深色 UI 录屏、字幕烧录、
  字号较大。小字号、浅色、无字幕的素材可能读不出。
- **仍然没有 ASR。** 二遍精读拿到的仍是字幕，不是语音。
- **triage.mjs 未删除但已弃用。** `timeline.origin.json` 的 `sampling.rejected` 段记录了这个决定。
