# 02 · n=2：一条真直播素材，推翻了我上一轮的建议顺序

**Status:** 实验记录 · 含撤回建议
**Date:** 2026-08-09
**素材：** `2026-07-18-21-40-27.mp4` —— 抖音直播录像，27 分 43 秒，1080×1920 竖屏，**无烧录字幕**
**上一轮的建议：** 「先拿真素材破 n=1，再补 ASR 通道」 → **顺序错了，见 §2**

---

## 〇、为什么选这条

[01](01-粗筛层-一个被推翻的方案.md) 的全部结论来自一条 295 秒的录屏讲解，n=1。
这条素材在四个维度上都不同：**长 5.6 倍 / 竖屏 / 直播而非录屏 / 没有烧录字幕**。
最后一条是关键——第一条素材的语义我全是读的烧录字幕，那是它的偶然属性。

画面构成：顶部固定贴片（U-KING 直播福利横幅）、中间屏幕共享区、右下角主播摄像头小窗。

## 一、采样架构：成立，且开销可预测

```
1663 秒 → 111 格 @ 15s → 3 张 7×6 联系表 → 49 秒
覆盖 100% 时长，无盲丢
```

规模扩大 5.6 倍没有出现任何问题。按实测速率外推 100 小时：**约 650 张联系表**
（[01](01-粗筛层-一个被推翻的方案.md) 里按 48 格估的是 500 张，同一量级）。
**两遍制的成本模型在 n=2 上站住了。**

## 二、语义提取：塌了 —— 这一条推翻了我的建议顺序

一遍粗读读完三张表，我能给出的全部东西是**场景分段**：

```
0–345s      主播全屏站立讲话，屏幕共享区空白（约 6 分钟纯口播）
360–465s    摄像头缩为小窗，屏幕出现浏览器 / OpenClaw 终端
480–825s    文档、网页、「AI 优化大师 79 分」、广州/杭州旅游海报、宇航员登月图
840–1425s   大段深色终端与长文档
1440–1545s  网页「把 AI 变成能用、能卖、能增长的产品」
1560–1663s  终端输出，收尾
```

**我不知道他在说什么。** 不知道哪句话说到了客户痛点、哪一刻有人下单、哪段是废话。
`value` 这个字段在这条素材上**根本没有依据可写**。

第一条素材能产出 13 个带价值判断的事件，靠的是字幕烧录在画面里——
`timeline.origin.json` 的 `V-NO-ASR` 原文写的是：

> 本片语义读自画面烧录字幕……这是这条素材的偶然属性，不是管线能力。

n=2 把「偶然属性」四个字坐实了。**在没有文本通道的素材上，整条管线只剩一个分镜表。**

### 所以上一轮的建议是错的

我上一轮说：先拿真素材破 n=1，再补 ASR 通道。理由是「先知道方案 B 在你真正的素材上成不成立」。
结果是：**方案 B 的采样部分成立，语义部分不成立，而不成立的原因正是那个我建议往后放的通道。**
n=2 这个实验本身证明了它该排在前面。

`V-NO-ASR` 从「已知缺口之一」升级为**唯一阻塞点**。

## 三、顺带发现一个真杠杆：自动裁掉「全程不变」的区域

直播素材的贴片全程一个像素不变，却占着联系表的像素预算，也就是真金白银的 token。
测一下有多少：整段素材 15s 抽帧、逐帧差分求均值，按 20 条横带测时间活跃度。

```
y   0%– 30%   YAVG = 54.00 54.00 54.00 54.00 54.00 54.00     ← 恰好基线，全程静止（贴片）
y  30%– 70%   YAVG = 55.56 63.78 63.95 66.60 68.29 66.40 61.74 60.27   ← 活跃区
y  70%–100%   YAVG = 55.02 54.00 54.00 54.00 54.00 54.03     ← 恰好基线，全程静止（黑边）
```

**65% 的画面高度是死的。** 裁掉之后，同样的成本下屏幕共享区的内容从「看不清」变成可读：
「AI 优化大师 79 分」、ClawX 工具箱里逐项列出的 Claude Code CLI / Codex CLI / OpenClaw /
Hermes / Obsidian、「免费送工具、双倍算力」、广州与杭州的海报页。

复现：`node sheet.mjs n2/live.mp4 --stride 15 --cols 7 --rows 6 --cell 240 --auto-crop`
对比：`n2/pass1/sheet_02.jpg`（未裁）vs `n2/pass1c/sheet_02.jpg`（已裁）

`basis: measured`，20 条横带的原始数值写进 manifest 的 `crop.evidence_band_yavg`。

## 四、但自动裁剪自己就是一次「把影子当对象」

它按**时间活跃度**裁。而活跃度不等于重要性——这两个恰好是影子与对象的关系。

**已实测的失败：主播摄像头小窗被裁掉了。** 它面积小、变化幅度远小于全屏滚动的文档，
于是被判为低活跃。而对一条直播来说，主播的表情和手势是**情绪通道**，
在没有 ASR 的情况下它几乎是唯一还剩下的价值信号——结果被一个"客观测量"顺手删了。

同理会被误删的还有：固定价格牌、常驻字幕条、台标里的品牌名。**静止不等于无关。**

处理方式（不是修好，是承认）：
- 该行为与代价写进 manifest 的 `crop.statement`，进包而不是进 README
- 加 `--keep-y <y0> <y1>` 手动指定，此时 `crop.basis` 从 `measured` 降为 `declared`
- **不默认开启 `--auto-crop`**

## 五、n=2 之后，四条结论的状态

| 结论 | n=1 | n=2 | 现状 |
|---|---|---|---|
| 两遍制采样（粗读全覆盖 → 精读） | 成立 | 成立 | ✅ 两条素材，两种形态 |
| 成本模型（100h ≈ 500–650 张表） | 估算 | 实测外推 | ✅ 同量级 |
| 声学/场景粗筛无效 | 实测无效 | 未复测 | ⚠ 仍 n=1 |
| **语义提取（value 判断）** | 成立（靠烧录字幕） | **不成立** | ❌ **依赖素材偶然属性** |

## 六、诚实边界

- **n=2 仍然是 n=2。** 两条素材都是同一个人、同一个产品、同一类题材（卖 U-KING）。
  真正的多样性（他人素材、非销售题材、多机位、实拍生活）一条没有。
- **§2 的"塌了"是我的主观报告，没有量化。** 我说"我不知道他在说什么"，这本身是断言。
  能支撑它的客观事实只有一条：这条素材没有任何文本通道可读，而第一条有。
- **自动裁剪的 65% 是这条素材的数字**，不是通用结论。不同直播布局差别很大。
- **`--auto-crop` 只在这一条素材上验过。** 通篇活跃的素材（实拍、运镜）会走 `return null`
  的分支不裁，但这条路径没有被真实素材测过（`unverified`）。
- **摄像头被裁这件事，是我先做了裁剪、再回头看才发现的**，不是设计时预见的。
  `T-NO-SEMANTICS` 那次是"边界写对了还是往坑里跳"，这次是"根本没想到"。
