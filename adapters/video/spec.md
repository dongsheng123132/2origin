# 本象 · video 方言 v0.1

**Status:** 方言草案（**不是新协议**）
**归属：** 本象协议 5 个概念的一个方言，与 Story / Office / CAD / xlsx / Memory 同级
**目标位置：** `本象协议/adapters/video`

> [00-极简核心](../../docs/00-极简核心.md) 硬规矩：
> **新方言 / 新协议若不能用这 5 个概念说清，就是在偷偷变大。**
> 下面这张表填满了，且五格里没有一个新概念 —— 所以它是方言，不进核心评审。

## 方言自检表

| 概念 | video 方言的"它" | 实例 |
|---|---|---|
| **对象** | 事件（一段有语义的时间区间） | `ev:e10` = 200–224s「AI 出图并全屏展示」 |
| **引用** | `<file>@<sha256前8>#t=<start>,<end>` | `src.mp4@888ac30f#t=200,224` |
| **投影** | 同一本象按不同目标生成的成片 | `douyin_30s` / `wechat_90s` / `full_edit` |
| **事务** | 保留 / 丢弃 / 改口径重投影 | 改 `projections.*.pick`，不动 events |
| **校验** | 指纹新鲜度、时间码值域、覆盖率、判据来源、边界完整性 | `validate.mjs` |

## 可信引用 5 属性核对

| # | 属性 | video 方言怎么满足 |
|---|---|---|
| 1 | 极小 | 引用是 `文件@指纹#时间码`，比被指的那段视频小 6 个数量级 |
| 2 | 稳定 | 素材不变则引用不变；素材变则指纹变、引用**主动失效**（这正是要的） |
| 3 | 可解析 | `ffmpeg -ss <start> -to <end>` 即解析器 |
| 4 | 新鲜 | `source.sha256` + `duration_s`，`validate.mjs` 每次渲染前核对 |
| 5 | 单一真源 | 台词 / 画面的真源永远是素材。`gist` 是有损投影，由 `V-GIST-LOSSY` 声明，程序不得当台词用 |

## 三段式结构（v0.2）

```
events[]      本象：ref / gist / gist_from / evidence / prosody —— 只放能复核的
audiences[]   受众与口径：谁在看、按什么标准、什么时候定的
appraisals[]  投影：{event × audience} → value，带 basis / by / as_of
```

**value 不属于本象。** 同一个 10 秒片段，对开发者是干货、对小白是噪音；今年是爆点、明年是老梗。
价值是视频与观众之间的**关系**，不在视频里面。v0.1 把它写进 events 就是把一个投影当成了事实——
这也是校验器那句「100% 的估值是不可复核的断言」的真正含义：不是标注得不够努力，是**位置放错了**。

实测收益（v0.1 结构上做不到的）：同一条直播挂两个受众，L09「一键把工具都装上」
在抖音受众下 0.90、在开发者受众下 0.25——**0.65 的差**，两条投影的选段完全不同，互不覆盖。
`dev_talk_5min` 的 pick 由 appraisals 推出，不再手工划。

其余好处：口径过期时废掉整组 appraisal，本象不动；拿到真实数据时**新增**一条
`basis: measured`，旧断言不删——这正是 A5 要的可对比记录（校验器会以 measured 为准）。

## 三个必填字段（这个方言的全部创新，且都是老原则的落地）

### `basis` + `gist_from` —— 不让断言冒充观察

**两件正交的事，必须分成两个字段。**

```
basis      value 的判据来源
           measured  有外部数据支撑（完播率、点赞、下单、留人曲线）
           observed  value 本身就是可直接观察的事实，不含审美判断
           asserted  模型/人的判断（爆点、卖点）—— 必须带 criterion + as_of + by

gist_from  gist 的来源
           read-on-screen  从画面读到（烧录字幕、UI 文字）
           transcribed     从音频转写（必须给可复听的 ref）
           described       自己概括的，非原文
```

价值判断本来就是断言，**A1 的解法不是把断言变成观察，是不让断言冒充观察**。

> 这两个字段一度是一个。加 ASR 时我给事件标了 `basis: transcribed`，校验器立刻报
> 「0% 的价值判断是断言」——**转写来源可靠，不等于那个 0.95 分不是我拍的**。
> 一个字段装两件事，断言就重新隐身了。拆开后两份 timeline 都诚实地报 100% 断言。
> 详见 [03-语音通道](docs/03-语音通道-阻塞点解除.md) §5。

`criterion`（按什么口径）和 `as_of`（什么时候）是 A5 的落地：口径会过期，
过期的分不该长得和新鲜的分一样。

### `grades` / `dimensions` —— 判断与决策分离（v0.3）

> **归属：** 「LLM 只出离散档 → 确定性函数加权 → 另一阶段才做选择」这个拆法来自 **MENTIS**
> （arXiv 2607.27201，Hao Fei / Yiran Zhao）的 branch evaluation 阶段。
> 本方言引用它，**不声称原创**。核实过程见
> [03-心智世界建模-先例实查与本象定位](docs/03-心智世界建模-先例实查与本象定位.md)。
> 对应的公理（bugscope A3）本仓库早有，但在此之前**没有任何一个方言落地过**。

`basis` 解决了"这个分是不是断言"，剩下两件事它管不了：

1. **这个分由什么构成？** `value: 0.94` 把"钩子强不强""说清楚没有""值不值得看完"揉成一个数，
   揉进去就再也问不出"到底哪一项拉低了它"。
2. **那个 4 是哪来的？** 编的。问模型要浮点，它就给你假精度——它内部没有 1% 的分辨率。
   v0.1 的 `value: 0.92` 正是这么来的（[00-反思](docs/00-反思-bugscope审视.md) §三·A1）。

v0.3 把打分拆成两层，**模型无权直接写 `value`**：

```
判断层（模型出）  appraisals[].grades   = {hook: 4, clarity: 3, payoff: 5}   只能是整数 1–5
决策层（公式算）  audiences[].dimensions = {hook: .45, clarity: .2, payoff: .35}
                  档位映射 {1:0, 2:.25, 3:.5, 4:.75, 5:1}
                  value = Σ 权重 × 映射(档位)      ← 校验器重算比对，不符报 error
```

三条硬规矩：

- **档位必须是整数 1–5。** 写 `4.5` 等于偷偷把五档变成九档——档位就是分辨率。
- **权重必须归一。** 不归一，value 就不再落在 [0,1]，跨受众也没法比。
- **`veto` 压过一切。** 一个 5 档的爆点如果露了没授权的脸，正确分值是 0 而不是 0.9——
  加权算不出这个，所以否决单独成路：`veto: {reason}` → `value` 必须为 0。

**这不提高准确率。** 它做的是让分数诚实地暴露自己的分辨率：五档就是五档，写不出 0.94。

### 决策要对判断负责（v0.3 的另一半）

拆完打分还剩第二个决策：**哪几段真的进成片**。v0.2 里 `projections.*.pick` 是模型直接写的数组，
旁边一句散文 `logic`。于是同一个模型既说"e02 值 0.94"、又说"我不剪它"，两句话之间没有任何东西对得上。

本方言**不假装剪辑是个算法**（它不是）。只要求一条：

> **判断层说值钱的东西，决策层扔掉时必须点名。**

`hi-value-silently-dropped`（error）：某事件在该投影受众下 `value ≥ threshold`（默认 0.7）、
未被任何 `pick` 段覆盖、且 `dropped` / `logic` 里**没出现它的 id**。
反向的 `low-value-silently-kept` 是 warn——低分保留通常是对的（承上启下、节奏、交代），但理由要写下来。

⚠️ **点时间码不算数。** 上线当天就抓到一例：`douyin_30s` 的 `dropped` 写着
`"275-287s 含 286s 糊帧"`，那个区间恰好是 `e13` 的 `t`，人能看懂。但二遍精读一改边界，
这句散文会**静默过期**，而 id 不会。这就是引用优先 ⑤ 的双份账本，所以校验器只认 id。

### `limits` —— 第七要素进包

沿用 `本象协议/compiler/limits.mjs` 的五种 kind（`degraded` / `uncovered` /
`undetectable` / `lossy` / `unverified`），字段 `{code, kind, scope, statement, remedy}`。
**AI 不读 README，它读包。** 空清单不合法——`validate.mjs` 直接报 error。

### `sampling` —— 说清自己看了多少

**两遍制：粗读全覆盖 → 高价值区间精读。**

```
pass1  整条素材，stride 15s，48 格/张 @200px  → 100% 时长覆盖，时间分辨率 15s
pass2  只对 value≥0.7 的区间，stride 1.5–2s   → 定位真正的边界与爆点
```

不做「按信号丢素材」的粗筛。原因见 [01-粗筛层](docs/01-粗筛层-一个被推翻的方案.md)：
声学/场景粗筛实测加权召回 33.4%，**低于随机基线 40.7%**，且丢掉的部分无法自述丢了什么（A4）。
两遍制的限制形状不同——不是「59% 素材没人看过」，而是「短于 stride 的事件可能掉进格缝」，
**可量化、可用二遍补**。

成本：100 小时 500 张联系表（原始 5s 方案 3,600 张，失败的声学粗筛 1,464 张）。

二遍不是可选项。实测三个高价值事件里有两个的剪辑点在一遍粒度下是**错的**
（e10 剪到了铺垫不是爆点；e13 压在一段镜头晃动的糊帧上）。
`validate.mjs` 的 `hi-value-not-refined` 会盯着这条。

### 纯音频素材：默认关掉 omni 复核

实测对照（21 分钟纯直播录音 vs 27 分钟带屏直播）：

| | 纯音频 | 带屏视频 |
|---|---|---|
| 改动里纯标点/语气词占比 | **46%** | 18% |
| 实质用词改动 | 54% | 82% |
| 实质改动的质量 | **有对有错** | 明显净正 |

纯音频那 54% 里，改对的有「龙翔→龙虾」「600G→六十四」（靠上下文推出来的），
改错的有「九十九→九九十九」「能不能够→能不能过」，还有「window 10→Windows十」
这种把阿拉伯数字中文化的倒退。

原因见 [06](docs/06-术语库负结果与一个机制发现.md)：**omni 的核心优势是读屏幕。**
没有屏幕这条通道，它退化成"另一个 ASR"，净收益大幅下降而引入新错的风险相对上升。

**建议：纯音频默认 `--no-refine`，只对已知含专有名词的关键段落单独开。**

### `crop` —— 裁掉全程不变的区域（可选，默认关）

直播素材常有固定贴片压掉大半画面高度，全程一个像素不变，却占着联系表的像素预算。
`--auto-crop` 用整段素材的时间差分图测出静止横带并裁掉。实测一条 27 分钟直播：
**65% 的画面高度是死的**，裁掉后同样成本下屏幕内容从看不清变为可读。

**但它按「时间活跃度」裁，而活跃度不等于重要性——这两个是影子与对象的关系。**
已实测的失败：主播摄像头小窗因面积小、变化幅度小于全屏滚动文档而被裁掉，
情绪通道随之丢失。所以默认关闭，`--keep-y` 可手动指定（此时 `basis` 从 `measured` 降为 `declared`）。
详见 [02-n2](docs/02-n2-真直播素材.md) §3–4。

### 语音通道（必需，不是可选）

`value` 判断依赖能读到"说了什么"。n=2 实测（27 分钟直播，无烧录字幕）：
没有 ASR 时一遍粗读只能产出**场景分段**，`value` 没有任何依据可写。

```
node asr.mjs <视频> --engine bl        # 阿里云百炼 fun-asr，56.7x 实时，句级+词级时间戳
node asr.mjs <视频> --engine whisper   # 本地 faster-whisper，离线兜底
```

本地 whisper small 在中文口播直播上**实测基本不可用**，会自动标注 `A-LOCAL-DEGRADED`。
「有兜底」不等于「兜得住」。

打开之后，那条直播的最高价值三段全部落在视觉通道给不出信息的区间（前 12 分钟画面只有一个人站在白墙前）。
四条通道的实测对照（虾盘云无 / 腾讯未开通 / 阿里 nls 要两道手工步骤 / 百炼可用）见
[03-语音通道](docs/03-语音通道-阻塞点解除.md)。


### 引擎选型（八个实测横评，见 [05](docs/05-八个引擎的横评与一条结构性结论.md)）

| 用途 | 选谁 |
|---|---|
| 时间码骨架（默认） | 百炼 fun-asr —— 56.7x 实时，句+词级时间戳 |
| 说话人分离 / 韵律 | 腾讯 asr —— 唯一给 SpeechSpeed / EmotionalEnergy / SilenceTime / SpeakerId |
| 高价值区间复核 | bl omni —— 低频词准确度断层领先，无时间戳由 ASR 补 |
| 离线兜底 | faster-whisper —— 中文口播实测基本不可用，只是「有」不是「能用」 |
| 不要用 | OpenRouter 音频模型 / SenseVoiceSmall / MiniMax（无 ASR） |

**为什么必须分工，而不是选一个最好的：**
值钱的信息高度集中在低频词上——产品名、价格、关键数字、领域术语。
而信息量大的词恰恰是先验概率低、声学证据不足以定案的词，ASR 的语言模型先验在这些词上**帮倒忙**
（把「美金汇率」纠正成「美金会议 / 美体会议 / 北京会议」，八个引擎里只有 omni 听对）。
所以 ASR 管覆盖与时间码，omni 管把值钱的词听对。


### 口播型素材：用句边界定剪辑点，不要手工估

实测两处错：`[120,150]` 把最强钩子腰斩（那句 148.16s 才开始）、`[543,558]` 选到铺垫而非卖点
（真正的卖点在 588.63s，**差 45 秒**）。两处 ffmpeg 都不报错、validate 也查不出——时间码完全合法。

```
node snap.mjs <timeline> <asr> --find "35万"            # 按台词直接查时间码
node snap.mjs <timeline> <asr> --projection X --write   # pick 吸附到 ASR 句边界
```

比二遍抽帧精读更准也更便宜。口播型素材的第二遍应该走这条，而不是加密抽帧。

### 时间戳不烧进画面

联系表画面里只烧**格号**（`%{n}`，帧计数器），格号→时间的映射只在 manifest 里，
由驱动抽帧的同一个 stride 常量算出。**一个公式，一个真源。**

上一版把时间戳烧进画面用的是 `t*5`——第二个时间公式，和 `fps=1/5` 各算各的。
它错了以后联系表看起来完全正常，下游时间码全错，管线一声不吭。修法不是加检查，
是让第二份公式不存在（引用优先 §1：结构上让漂移不可能发生）。

## 校验器保证什么、不保证什么

**保证**（`validate.mjs`，全部有复现用例）：

| 失效 | 为什么必须在入口拦 |
|---|---|
| 时间码基准错（如 ×5） | ffmpeg 会成功输出时长精确的 mp4 并报 OK |
| 素材被同名替换 | 同上，旧时间码剪新视频，静默错位 |
| pick 越界 / 剪没人看过的素材 | 同上 |
| value 无 basis | 断言冒充观察 |
| 断言无口径 / 无日期 | 分数悄悄过期 |
| value 与档位×权重算出来的不符 | 判断权与决策权重新合到一只手里（A3） |
| 档位越界 / 权重不归一 / veto 却有分 | 假精度与不可比的分数 |
| 高价值事件被投影丢弃却没点名 | 判断说值钱、决策扔掉，中间无人对账（A3+A4） |
| gist 无 gist_from | 读来的、听来的、自己编的分不清 |
| 转写来源却没给可复听 ref | 声称"我听到了"本身就是声称 |
| 缺 limits 段 | 下游把有损表示当本体用 |
| 台词被复制进事件（双份账本） | 副本与素材漂移 |

**不保证**：

- 查得出"这条边界写得合不合格"，查不出**"明明有个坑却没写下来"**。
  第七要素降低的是"不知道自己不知道"，消灭不了"知道却不说"。
- 不判断成片好不好看。`value` 是断言，本方言只保证它**标注自己是断言**。
- **查不出"剪辑点选错了"。** 实测两次：钩子被腰斩、卖点差 45 秒，时间码全部合法，
  validate 一声不吭。这类只能靠 `snap.mjs` 换方法规避，不能靠校验发现。
- 时间码值域检查依赖 ffprobe。ffprobe 不可用时该检查**不成立**，校验器会明说。
- **n=2**，且两条素材同一个人、同一个产品。声学粗筛无效那条结论仍是 n=1。
