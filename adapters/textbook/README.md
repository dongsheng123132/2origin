# textbook 方言 —— 一本教材的本象

> 责编发来七条审稿意见，散文写的。改完之后怎么证明改到位了？
> 靠人眼把 285 页、707 张图翻一遍，翻到第 500 张时已经忘了第 30 张当初是怎么处理的。
> 这份方言把七条意见编译成 19 条机器可判定的约束，于是「改完了没有」从人眼抽查
> 变成 `diagnose` 的红点计数——**红点单调下降是交付前唯一不靠人眼的进度指标**。

```bash
node adapters/textbook/import.mjs 教材.docx                    # 体检统计
node adapters/textbook/import.mjs 教材.docx --json              # 图/表/任务清单
node adapters/textbook/import.mjs 教材.docx --origin 书.origin --decisions 责编意见.json
node compiler/cli.mjs diagnose 书.origin                       # 红点
# 批量改稿（--dry 只报不写）：把无歧义的责编意见执行掉，改完重跑 diagnose 验收
node adapters/textbook/normalize.mjs 教材.docx 改后.docx --debracket --tbl-flatten 4 --line 480 --size 24 --indent
node adapters/textbook/selftest.mjs                            # 60 条自检（含 24 条反向用例 ✗）
```

## 为什么 office 方言不够用

office 方言的骨架是 `chapter:第X章` / `article:第五十条`——那是红头文件和法规。
拿它吃一本 35MB 的职教教材，实测：

```
共 2001 个结构对象：{"chapters":0,"articles":0,"tables":96,"refs":[]}
```

96 个表认出来了，章、条、引用一个都没有。教材根本不长那样：
它的骨架是**项目 → 任务 → 栏目**，它的引用是**图1-6 / 表2-3**。

## 九类对象

| 对象 | ID 形如 | 是什么 |
|---|---|---|
| `book:` | `book:机械零部件测绘` | 书（页数估算、字号/行距变体数、悬空引用） |
| `proj:` | `proj:1` | 项目一 |
| `task:` | `task:1-2` | 项目一任务二（含 `sections_missing`） |
| `sect:` | `sect:1-2/知识链接` | 栏目（含 `bracketed`：栏目名带不带【】） |
| `fig:` | `fig:1-6` | 插图（图号、图名、在不在表格里、有没有被正文提及） |
| `tbl:` | `tbl:2-3` | 表格 |
| `img:` | `img:media/image12.png` | 图片资源（**真实像素**、在不在表格里、有没有图注） |
| `decision:` | `decision:no-steps-in-table` | **责编的一条意见**（pending / applied / verified） |
| `spec:` | `spec:redraw` | 施工规范（线型 / 字高 / 图层名） |

**重心是 `decision:` 和 `spec:`，不是 `fig:`。** 图号连不连号、图注重不重名，正则扫一遍就有
答案——本象自己的实验说得很清楚，这类**能从正文直接读出来的状态**，裸模型和检索都够用。

**本象唯一被实验钉死的优势维度是「证据链」，不是「状态准确率」**
（[论文 v0.4](../../benchmark/shadowbench-w/paper/shadowbench-w-paper-en-v0.4.md) §5.3 消融）：
一条纯提示词臂（只要求模型维护显式状态）就能拿到状态准确率优势的 **94%**，
且**比裸模型还省 token**；全套机制只多 2.5 分，**不显著**（p = 0.47 / 0.72）。

**但提示词臂产不出证据链——不是产得差，是结构上没有「信念 vs 依据」的区分**：
可溯源证据覆盖率 **15.0% / 27.5% vs 0%**。

> 所以这套东西卖的不是「状态记得准」，是「**每一条状态说得出它凭什么**」。

教材工程里恰好只认后者：**责编的这条意见落实在哪一段、被什么验证过、谁改的、改之前是什么样**——
交付验收要的是账本，不是断言。这就是 `decision:` 的 pending → applied → **verified**
三态，和「红点单调下降是唯一不靠人眼的进度指标」。

## 责编意见 → 机器约束

这是本方言最值钱的一段。散文没法验收，编译成下表才能。

| 审稿意见原文 | 约束 id |
|---|---|
| ① 层级按我社推荐（栏目名不带【】） | `sect-not-bracketed` · `task-sections-complete` |
| ② 图表按项目分两级注写（图1-1、表1-1） | `fig-num-two-level` · `tbl-num-two-level` |
| ② 所有图表均需排号、命名 | `fig-name-required` · `fig-num-unique` · `fig-name-unique` · `every-img-captioned` |
| ② 并在正文中提及 | `every-fig-referenced` |
| ③ 量具名称参考国标 | ⚠ **机器判不了 → limits** |
| ④ 宋体小四 2 倍行距 | `body-size-uniform` · `linespacing-uniform` |
| ④ 260 页以内 | `pages-within-limit` |
| ④ 文与图、文与表一一对应 | `no-dangling-fig-ref` · `no-dangling-tbl-ref` |
| ⑤ 任务描述到实施的逻辑更清晰 | ⚠ **机器判不了 → limits** |
| ⑥ 任务名称更具体 | ⚠ **机器判不了 → limits** |
| ⑦ 绘图步骤不要放在表格里 | `no-fig-in-table` · `no-img-in-table` |
| （印刷底线，非意见原文） | `fig-print-ready` |
| （跨会话施工的命根子） | `decision-all-applied` |

判不了的三条**必须留在 limits 里，不许假装判了**。
`diagnose` 全绿 ≠ 书没问题，只 = 机器能查的那部分没问题。

## 这不是从零写的

判据的实质内容来自 `ShadowOS = Harness OS/demo/book-project/`（**book/0.1**，2026-08-09）：
`observe-docx.mjs` + `book-core.mjs` + `check-book.mjs` + `verify-book.mjs`
（35 条判据 / 29 条反向用例，**专门验证体检器自己**）+ `renumber.mjs`（改稿）
+ `build-report.mjs`（出报告）+ `task.origin.json`（2origin/0.2 任务状态包，含 facts / decisions / learnings）。

本方言相对它新增的只有三样：**项目/任务/栏目骨架**（book/0.1 按「项目-任务-序号」三级图号设计，
吃不了两级编号的教材）、**`decision:` 对象**（责编意见变成可追踪状态）、
**图片埋在表格里的判据**（意见⑦）。
分类规则、阈值、反向用例的做法一律照抄 book/0.1——那是用真数据换来的，别自作聪明改。

## 实测（《机械零部件测绘及成图技术》35.2MB / 5 项目 / 22 任务 / 707 图）

707 张图**先分三类再谈红点**：插图 530 · 行内符号 176 · 找不到宿主 1。

```
对象 1179｜关系 623｜约束 19/19 可判定

  487  插图最短边不低于 800px（行内符号与矢量图不判）
  393  插图没有图注（意见②）
  336  插图埋在表格里（意见⑦）
  132  栏目名带【】（意见①）
   12  表号还在用 表4-1-1 三级编号（意见②）
    7  责编七条决定全部 pending
    1  正文引用的图号无对应图注 —— ["2-5-6","3-1-2","3-1-21","5-2-21"] 旧版三级编号残留
    1  图名重复 11 组（精密平口钳 / 端盖 / 活塞杆 / 箱盖 …）
    1  正文字号不统一 · 1 行距不统一（5 种）· 1 页数超限（估算 270 页 > 260）
 1372  ── 红点合计
```

> 首版报的是 **1888**，差出来的 **516 条（27%）全是假警**，来源是下面第 ④ 个坑。
> **判据器首版一定会误报**——上线第一件事不是跑真数据，是把首轮误报逐条钉成反向用例，
> 否则下一版原样复发。这句话 book/0.1 的 learnings 里写着，本方言首版还是照样栽了一遍。

## 七个坑（都是实测栽出来的，写在这里省得下次再栽）

**① 图号与图名之间是两个空格。** 「图1-1␣␣精密平口钳」——按空白切并排图注会把图名切没，
造出 35 个「图名为空」的假红点。正确切法是按**下一个图号的起点**切，两种排版才能同时兼容：
并排的「图1-2 测绘对象␣␣␣␣图1-3测绘资料准备」和单条的「图1-1␣␣精密平口钳」。

**② 只判图注会得到假绿。** 埋在步骤表里的那几百张图**恰恰一个图注都没有**，
只判 `fig:*.in_table` 得到 0，真实是 504 张 `img` 在表里。责编意见⑦ 的靶子是图片资源，不是图注。

**③ docx 里的图不都是 DrawingML。** 这本教材 719 张图走老式 VML（`w:pict` / `v:shape`
`style="height:602.2pt"`），只有 54 张走 `wp:extent`。不解析 VML 尺寸，页数估算塌成 156 页
（真实 285），「260 页以内」直接假绿。

**④ 分辨率判据只对插图生效——这个坑踩过两次。** 正文里的 φ / ± / Ra 是 25px 左右的小图，
按插图标准判就会报「印刷必糊」：book/0.1 首版因此产出 108 条假警，
**本方言首版原样复发，1888 条里 516 条（27%）是假的**。分三类，照 book/0.1 的原样：

```js
if (!hosts.length)                    role = 'unplaced'  // 找不到宿主段落 → 不敢判
else if (maxPx < inline_max_px)       role = 'inline'    // 60px：绝对尺寸压倒一切
else if (min(hosts) > host_text_len)  role = 'inline'    // 15 字：嵌在行文里
else                                  role = 'figure'
```

三处细节都别改成看起来更整齐的版本：**条件是 OR 不是 AND**（写成 AND 只捞出 86/202 张）；
**阈值 60px / 15 字是实测值**；**`unplaced` 必须单列一类**——「找不到宿主就当插图判」
等于把未知当已知去报警，是判据最常见的撒谎方式。

**⑤ 去【】要白名单，不能见【】就去。** 实测这本书第 9085 段写着「单击**【定位】**搜索」——
那是软件按钮名。判据必须是**整段就是一个白名单里的栏目名**，两个条件缺一不可。
白名单在 `dialect.mjs` 的 `BRACKETABLE_SECTIONS`，比 `STANDARD_SECTIONS` 宽
（各书自己多出来的栏目：任务目标 / 知识与拓展 / 三类目标）——叫什么、要不要并栏是责编说了算，
但「栏目名不带【】」对它们同样成立。

**⑥ 判据数的那批，必须与改稿器改的那批是同一批。** 首版 `--line 480` 只改 ≥15 字的正文段，
`import.mjs` 却把 >8 字的、连同图注与 (a)(b) 组图标注一起算进「行距变体数」，
于是**改完红点不降**——看上去像稿子没改好，其实是两边在数不同的东西。
两侧的正文定义（`isCaptionLike` 与 `isBody`）改一处就要同步另一处。
这与「行内符号假警」是同一族错：拿不是靶子的东西去判靶子的判据。

**⑦ pPr / rPr 的子元素有 schema 规定的顺序。** `<w:b/>` 插到 `<w:rFonts>` 前面，
Word 多半容忍——但那是在赌客户那台机器上的 Word 宽容，交出去的稿子不赌这个。
插入一律走 `upsertOrdered()`，顺序表见 `normalize.mjs` 的 `PPR_ORDER` / `RPR_ORDER`。
另有一条：表注常常**不空格**就接表名（「表4-1-4常用铸铁的名称」），
识别表注不能要求编号后是空白；但也不能什么都放行——「表4-1的技术要求…」那是正文在提这张表。

## 已知边界（limits，如实标注）

- **图注与图片的绑定是弱判据**：只在图注前后 4 段内找图片。一张图被挪到别的图注下面，抓不到。
- **量具/零件各部分名称是否符合现行国标**（意见③）机器判不了：要人去工标网查现行、道客巴巴查条文。
- **「逻辑是否清晰」「名称是否够具体」**（意见⑤⑥）是写作判断，不是结构判断，不判。
- **A/B/C 三类图（软件截图 / 原理图 / 工程图）的归属由人判**，不自动分类——它直接决定重绘工作量与报价，不能让机器猜。
- **页数是估算**：内容估算 × 1.35 排版损耗系数，**该系数的标定样本只有 1 本书**
  （内容 200 页 / 目录实测约 285 页），不该当成常识；再标几本教材就该修正。

## 顺手修掉的一个上游 bug

office 方言的入口守卫写成「文件名叫 import.mjs 就跑 main()」，导致 cad 与 textbook 方言
（入口同名）一 `import` 它就把整本书的 markdown 打到 stdout。已改为同时要求路径在 `/office/` 下。
