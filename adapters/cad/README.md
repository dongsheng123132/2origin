# CAD 方言 —— 图纸一致性

> 图纸不一致今天靠人拿放大镜核对，错了往往到施工现场才发现。
> 这些规则本来就写在制图规范里，只是从来没有机器守着。

## 用

```bash
node adapters/cad/import.mjs 图纸.dxf 图纸.origin --name A-101
node ../../compiler/cli.mjs diagnose 图纸.origin      # 有 error 时退出码 1，可串进出图前检查
```

实跑输出（对 `fixtures/A-101.dxf` 这份真图纸）：

```
导入 A-101：5 图层、7 图元、4 文字（DXF AC1009）
⚠ 该 DXF 无实体句柄（R12 或更早）——ID 退化为内容哈希

error  constraint  图元不得留在 0 层｜ent:0/* 实有 1 个，应为 0 个
error  constraint  标注层的编号不得重复｜text:标注/*.content 出现重复：C2
error  constraint  门窗层的构件数量必须等于标注层的编号数量｜ent:门窗/* 有 4 个，text:标注/* 有 3 个，两处对不上
✗ 3 个 error 级问题
```

## 对象命名：图层编进 ID

`dwg:A-101` · `layer:门窗` · `ent:门窗/<id>` · `text:标注/<id>`

图层在 CAD 里本来就是语义分类（没人把窗画在墙体层），编进 ID 之后
「门窗层构件数必须等于标注层编号数」可以直接用通配约束表达，
校验器不需要任何领域知识——这是 CAD 方言没有给核心加一行代码的原因。

## 稳定 ID 的现实问题（必须先看这段）

本象的地基是稳定 ID，但**R12 格式的 DXF 里图元根本没有 ID**——
实体句柄（组码 5）是 R13 才普及的，而「另存为 R12」在国内出图流程里极常见。

| 文件情况 | ID | 后果 |
|---|---|---|
| 有 handle（R13+） | `ent:门窗/<handle>` | 真正稳定。挪动一根梁仍是同一个对象，改了什么一目了然 |
| 无 handle（R12） | `ent:门窗/<几何哈希>` | **退化**。图元一移动 ID 就变，版本对比会把「移动」看成「删了再加」 |

退化不隐瞒：包里写 `id_basis=content`，导入时 stderr 明确告警。
**要做真正的版本对比，导出时必须选 R13 以上——这是对出图流程的硬要求，不是建议。**

## 内置规则（全部来自制图规范）

| 规则 | 谓词 | 抓什么 |
|---|---|---|
| 图元/文字不得留在 0 层 | `count == 0` | 0 层图元关不掉层，出图时必然多画 |
| 编号不得重复 | `unique` | 两个 C2，施工按哪个下料 |
| 构件数 = 编号数 | `count equals_count_of` | 画了 4 樘窗只标 3 个编号 |
| 字高不得过小 | `range` | 小于图幅 1/300 等于没标 |

规则是**数据**（`dialect.mjs` 里一个数组），换个专业换一份规则即可，不改代码。

## 块引用：真图纸的主体

门窗、设备在真图纸里几乎全是块（`INSERT`），编号存在**块属性**（`ATTRIB`）里，
不是散落的文字。所以：

- `BLOCK` 定义 → `block:C-1500` 对象（带块内图形数与外框尺寸）。换型号时能查「谁用了这个块」
- `INSERT` → `ent:门窗/<id>`，带 `block`、插入点、旋转、缩放，
  包围盒按「减基点 → 缩放 → 旋转 → 平移」变换到世界坐标（DXF 规定的顺序，颠倒了就错位）
- `ATTRIB` 摊平成 `attr_NUMBER` 这样的**平字段**——谓词判的是「一个稳定 ID 上的一个具名字段」，
  嵌套对象进不了这套判定

### 规则集按图纸实际用法自动选

用块属性编号的图纸根本没有标注层文字。硬套「构件数 = 标注数」会得到
「4 樘窗 vs 0 个编号」的**假警报**——比不查更糟，因为几次误报之后没人会再看体检结果。
所以导入器先看图纸实际怎么编号，再决定用哪套规则，并把结论写进包里（`dwg:*.numbering`），
让人看得见而不是猜。

## 支持范围（不夸大）

- 读：R12（`POLYLINE`+`VERTEX`+`SEQEND`）与 R13+（`LWPOLYLINE`）都认；
  `LINE` / `CIRCLE` / `ARC` / `TEXT` / `MTEXT` / 多段线 / `INSERT` 块引用 + `ATTRIB` 块属性
- **不读**：`DIMENSION` 的关联几何、外部参照（XREF）、三维实体、嵌套块的内部图元展开
- **不写 DXF**。改图仍在 CAD 里做，本象只负责「读进来、守规矩、留证据」

## 验证

```bash
npm run test:cad     # 35 项，对着两份真 DXF 跑
```

| 夹具 | 来源 | 故意带的缺陷 |
|---|---|---|
| `A-101.dxf` | uking-cad 生成（外部工具，spec 留在 `A-101.spec.json`） | 图元留 0 层 / 编号 C2 重复 / 4 樘窗只标 3 个编号 |
| `B-201.dxf` | 本仓库 `make-blocks-fixture.mjs` 按 R12 规范手写 | 门窗重号 C1（第 1 樘与第 4 樘） |

**诚实边界**：`B-201.dxf` 未经 AutoCAD 往返验证——它证明解析器对得上规范，
不证明对得上真软件的输出。拿到真图纸要重新验一次。
这 35 项测的是「抓不抓得到」，不是「跑不跑得通」。
