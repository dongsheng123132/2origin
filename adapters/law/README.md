# 法律方言 —— 判决的依据链

> 判罚要有据可查、有法可依。今天这句话在判决书上兑现不了：
> 引的条文有没有失效、能不能作裁判依据、量刑怎么算出来的，
> 一份判决书里查不到答案——**依据链不是错的，是缺的**。

## 用

```bash
# 审计模式：对一份既成文书体检
node adapters/law/import.mjs adapters/law/fixtures/B-缺陷.txt /tmp/B.origin
node compiler/cli.mjs diagnose /tmp/B.origin      # 有 error 时退出码 1，可串进签发前检查

# 生成模式：量刑走事务，每一步带依据
node adapters/law/import.mjs adapters/law/fixtures/A-合规.txt /tmp/A.origin --staged
node adapters/law/sentence.mjs /tmp/A.origin --declare 7 --by 承办法官-李
node compiler/cli.mjs why /tmp/A.origin case:2026沪0101刑初123号.调节比例合计

# 收料：别人给来的材料，先看能查到什么程度
node adapters/law/intake.mjs 收到的.txt --split 收到的/   # 一坨多份的先拆开
node adapters/law/intake.mjs 收到的/*.txt

npm run test:law                                  # 95 项自测
```

**收料体检和判定是两件事，必须分开报。**`diagnose` 回答「这份判决有没有毛病」，
`intake` 回答「这份材料我能不能查」——混在一起会出现最坏的结果：
解析失败导致零 error，被读成「体检通过」。

```
收料体检：某某判决书.txt
✓  案号        （2026）沪0101刑初789号　刑事·初审
✓  裁判依据段  6 处引用，条文库命中 7，查无 0
✗  量刑评议表  缺失（判决书正文里本来就没有，不是材料的错）
可做：A 引用体检　/　D 正文对照
不可做：C 证据支撑　/　D 数字可复算
可用度 7/8
```

## 对象命名：把规范性文件的类别编进 ID

```
law:刑法/264                  法律
interp:法释2013-8/1           司法解释
adminreg: / localreg: / adminrule:   行政法规 / 地方性法规 / 规章
guide:法发2021-21/3           司法文件（法发字号）——**不是**司法解释
case: / fact: / evidence: / factor: / cite: / mention:
```

类别本来就是法律体系里的既有分类（没人会把部门规章当法律），编进 ID 之后
「刑事案件的裁判依据只能是法律或司法解释」就是一条通配约束，
校验器不需要任何法律知识——**这是法律方言只给核心加了 4 行显示代码的原因**。

## 这些规则不是编出来的

| 规则 | 出处 |
|---|---|
| 刑事、民事裁判文书应当引用法律、法律解释或司法解释；规章及其他规范性文件经审查确认合法有效的，只能在**说理**部分引用 | 法释〔2009〕14号 |
| 量刑三步：量刑起点 → 基准刑 → 按情节调节 → 20% 幅度内确定宣告刑；多情节**同向相加、逆向相减**（不是连乘） | 法发〔2021〕21号 |
| 自首减 40% 以下、坦白减 20% 以下、累犯增 10%-40%、从犯减 20%-50%…… | 同上，见 `dialect.mjs` 的 `FACTORS`（15 个常见情节） |
| AI 辅助结果只能作参考，不得代替法官裁判 | 法发〔2022〕33号 |

### 条文库的认知边界：`closed_world`

`lawdb.json` 顶层的 `closed_world` 决定了「库里查不到」该被读成什么：

| 取值 | 含义 | 查不到时判 |
|---|---|---|
| `true` | 本库**自称完备**，缺的就是伪造的。只有自造 fixture 这种封闭世界才配 | `not-found`（error） |
| `false`（缺省） | 部分覆盖，不敢自称完备 | `uncovered`（**warning**，未校验） |

**这不是可选的严谨，是实验能不能做的前提。**《刑法》第二百六十四条当然存在，只是不在
这份 20 条的样本库里；把它判成「查无此文」，就是在诬告一份没错的判决书。真文书必然大量
引到库外条文，若一律判 error，量到的假阳性率全是库的覆盖缺口，与校验器对不对毫无关系
——**这一轮唯一要量的就是假阳性率，那这场实验就白做了。**

缺省 `false` 是安全侧：**不敢自称完备的库，不许说别人伪造。**

`uncovered` 不会被静默吞掉：`citation-coverage` 这条警告级约束会把它单独报出来，
`intake.mjs` 也会在过半引用未覆盖时把「A 引用体检」从可做降级为不可做。理由与
`intake` 存在的理由是同一条——**没查 ≠ 查过没问题，也 ≠ 有问题**，
而最坏的结果是「零 error」被读成「这份文书的引用都合规」。

### 抓不到的两个，以及为什么

| 缺陷 | 为什么确定性门禁做不到 |
|---|---|
| **认定累犯，但查明段没有任何前科事实** | 需要判断「查明段这些句子是否构成前科认定」——语义推理，不是字段比对。可做的是把「前科」升格为必须显式认定的 `fact:` 对象，让漏认定变成字段缺失；但那要求文书结构化到今天没有的程度 |
| **引刑法第六十四条（追缴违法所得）来支持「应当从重处罚」** | 这正是 Stanford 说的 **misgrounded citation**：条文真实、有效、类型合规，就是不支持那句话。判定它需要读懂条文与命题的关系。本象能把「四类引用错误」压到「一类」，剩下这一类交给确认台（人类确认层） |

**把漏检写进目录并断言「抓不到」，是为了让边界成为被记录的已知项，而不是一次没人发现的沉默失败。**

## 拿到的不是结构化数据怎么办

判决书正文里**没有量刑的中间量**——量刑起点、基准刑、各情节调节比例写在量刑建议书与
量刑评议表上，在卷内，不在文书上。判决书只写一句「依法从轻处罚」。

所以导入器接受一个可选的【量刑评议表】段（办案系统内数据）。没有它时：

```
⚠ 未提供【量刑评议表】——量刑起点、基准刑、各情节调节比例不在判决书正文里，
  故 D 类（数字可复算）约束因字段缺失而未校验。这不是体检通过。
```

谓词遇到字段不存在自动跳过是核心的既有行为；导入器要做的是**明说哪些没查**，
而不是让「没报错」被读成「查过了没问题」。

## 边界

1. **不判案。** 法发〔2022〕33号 确立辅助审判原则。本方言管的是结论到依据的**可追溯性**，不是结论对不对。
2. **条文库要人维护。** `lawdb.json` 只是最小样本（20 条）。时间效力、修正案、司法解释废止关系是脏活，本象不消灭它，只是给它一个有 provenance 的落点——这是整个方案最大的隐性成本。
3. **没有法律场景的对照实验数据。** 上表全是**门禁能力**的度量，不是「本象 vs RAG」的效果对比。后者要跑 ShadowBench-L，见 [research/2026-08-法律场景评估.md](../../research/2026-08-法律场景评估.md) 第六节。
4. **`equals_ref` 缺口。** 正文对照目前把期望值固化成字面量（审计既成文书时正确，因为认定事实不再变动）。要在生成模式下持续成立，核心需要一个字段对字段的 `equals_ref` 谓词——`count` 已经有 `equals_ref`，标量谓词还没有。登记为 v0.2 候选，没在方言里私自补。
