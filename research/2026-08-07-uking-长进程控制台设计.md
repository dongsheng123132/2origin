# U-King 长进程任务控制台（Long-Running Task Console）

> 2026-08-07 · 状态：设计草案 → 待实现
> 用户需求（原话转述）：**在 U-King 里做一个「长进程项目」的环境和子板块**——
> 长时间任务，电脑不关机，可视化。可以启动、可以看到进展。比如 Mac Mini 里的任务，
> 在 U-King 里可视化，可以启动、看进展。

---

## 一、要解决什么

U-King 现在能管理「任务」（tasks.json，idle/active 状态），但那是**会话级任务**——
打开一个目录、开一个 Claude 会话，关了就没了。

**长进程任务**是另一类：它活在**另一台机器**（Mac Mini / 云服务器）上，跑**几天到几个月**，
本机要能：

| 能力 | 现状 | 目标 |
|---|---|---|
| 看状态 | 无 | 列表显示每台机器上的长任务：运行中/闲置/失败/上次运行时间 |
| 启动 | 无 | 一键触发远端任务（ssh 调 maintain-daily.sh 等） |
| 看进展 | 无 | 每任务最近一次运行日志、world state 摘要 |
| 长期存活 | 无 | 电脑不关机，任务持续跑（cron 在远端机器） |

## 二、架构：状态契约优先

控制台本质是**一个状态文件 + 一个查看器**。先定义契约，机器无关：

### 2.1 状态文件：`~/.uking/longrun/agents.json`

每台跑长任务的机器一个条目。Mac Mini 维护员每天把状态写到这里（通过 ssh+scp 或 Syncthing 同步）：

```json
{
  "version": 1,
  "updated_at": "2026-08-07T09:00:12Z",
  "agents": [
    {
      "id": "macmini-maintainer",
      "name": "本象协议维护员",
      "host": "macmini",
      "os": "macOS 15.6.1",
      "status": "running",
      "last_run_at": "2026-08-07T09:00:12Z",
      "last_run_duration_ms": 3240000,
      "last_run_result": "verify all green · 1 commit",
      "next_run_at": "2026-08-08T09:00:00Z",
      "schedule": "0 9 * * *",
      "log_tail": "✅ 全仓 verify 通过 · 19 条变异 0 漏网\n📦 提交 1 个 commit",
      "world": {
        "objects": 105,
        "changes": 517,
        "drift_rate": "8.3%"
      }
    }
  ]
}
```

### 2.2 机器侧：写状态的小脚本

Mac Mini 上维护员跑完一天后，写一段 JSON 状态 + tail 日志。已实现：
`scripts/maintain-daily.sh` 在结束时把 `last_run` 信息 append 到日志，
新加 `scripts/write-agent-status.sh` 生成上述 agents.json。

### 2.3 本机侧：同步 + 查看器

- **同步**：ssh `cat` 拉取 或 Syncthing 文件夹（推荐后者，Mac Mini 已有 Syncthing 生态）
- **查看器**：U-King 子板块，读 `~/.uking/longrun/agents.json` 渲染
  - 卡片列表：名称 / 状态徽章 / 上次运行时间 / 下一次 / 日志 tail
  - 操作：▶ 启动（ssh 执行 maintain-daily.sh）、↻ 重跑、📋 看完整日志
  - 只读优先：**启动远端任务需确认**（属于「对外操作」，见 hermes 契约硬边界）

## 三、U-King 集成方式

U-King 现有 `apps/` 注册制 + `tasks.json`。长进程控制台两种接法：

| 方式 | 做法 | 取舍 |
|---|---|---|
| **A. U-King 子板块** | 在 U-King UI 里加一个「长进程」页，读 agents.json | 原生体验，但需改 U-King 前端 |
| **B. 独立网页** | `website/longrun/` 下放一个只读 dashboard 页，读一个静态 agents.json | 零前端改动，Mac Mini 状态推到网站即可看 |

**建议：先 B 后 A。** B 一天能上线（静态页 + 定时同步 agents.json），
A 等 U-King 前端有空位再接。B 还能顺手成为 2origin.org 的「维护员公开状态页」——
让外界看到本象协议自己在被长期维护，本身就是最好的 dogfooding 广告。

## 四、状态字段契约（机器无关）

| 字段 | 类型 | 含义 | 必填 |
|---|---|---|---|
| `id` | string | 机器上唯一 ID | ✅ |
| `name` | string | 人类可读名 | ✅ |
| `host` | string | ssh config 主机名 | ✅ |
| `status` | enum | `running` / `idle` / `failed` / `never` | ✅ |
| `last_run_at` | ISO8601 | 上次开始时间 | ✅ |
| `last_run_duration_ms` | int | 上次耗时 | 有则填 |
| `last_run_result` | string | 上次结果一句话 | ✅ |
| `next_run_at` | ISO8601 | 下次计划 | 有则填 |
| `schedule` | string | cron 表达式 | ✅ |
| `log_tail` | string | 最近日志片段（≤4KB） | 有则填 |
| `world` | object | 本象 world state 摘要（objects/changes/drift_rate） | 可选 |

## 五、诚实边界

- 控制台是**观测层**，不是执行层——它看状态、触发任务，不假装自己是那个任务
- 远端任务的真实状态以**机器上的日志和 git log** 为准，控制台只是投影
- 启动/重跑远端任务 = 对远端机器操作，需用户确认（hermes 契约硬边界第 4 条）

---

> **一句话**：长进程控制台 = `agents.json` 状态契约 + 查看器。
> 契约先定义好，Mac Mini 维护员先写，网页查看器后渲染，U-King 原生页最后接。
