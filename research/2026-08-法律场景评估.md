# 法律场景评估：判决的「依据性」是不是一个状态追踪问题（2026-08-04）

> 结论先行：**是**，而且是本象实测优势唯一成立的那个维度的纯粹形态。
> 但本象在这里没有实验数据，法律方言的价值主张目前只是**结构论证**，不是**实测结论**。
> 本文给出可落地的方言设计与一个可证伪的实验计划（ShadowBench-L）。

## 一、「依据性」拆开是四个不同的问题

中文语境说的「有法可依、有据可查」，在司法文书里其实是四件事，失败模式各不相同：

| 子问题 | 官方要求 | 失败长什么样 |
|---|---|---|
| **A 引用存在且可引** | 法释〔2009〕14号：刑事、民事裁判文书**应当引用**法律、法律解释或司法解释；行政案件加行政法规。规章及其他规范性文件**不得作为裁判依据引用**，经审查确认合法有效的只能用于**说理** | 引了一条不存在的条文；引了部门规章当裁判依据；引了已废止的司法解释 |
| **B 引用真的支持该命题** | 法发〔2018〕10号 释法说理指导意见 | 条文是真的、也有效，但根本不支持那句话——Stanford 称之为 **misgrounded citation** |
| **C 认定到结论的链条完整** | 刑诉法证明标准；类案检索指导意见 法发〔2020〕24号（检索范围有优先级：指导性案例 → 最高法典型案例及生效裁判 → 本省高院 → 本院；须出具检索报告并随案归档） | 「本院认为」直接跳到结论，中间少一步；类案检索做了但没留痕 |
| **D 数字可复算** | 法发〔2021〕21号《关于常见犯罪的量刑指导意见（试行）》：量刑起点 → 基准刑 → 按情节调节 → 20% 幅度内确定宣告刑 | 每步调节比例合规，加总却对不上；同一金额在「认定事实」段和「本院认为」段写了两个数 |

**D 这一段值得单独看，因为它是确定性计算。** 指导意见给的是硬区间：

```
未成年（14-16 周岁）  减少基准刑 30%-60%
未成年（16-18 周岁）  减少基准刑 10%-50%
未遂                  比照既遂减少 50% 以下
从犯                  减少 20%-50%（较轻者 50% 以上或免除）
自首                  减少 40% 以下（较轻者 40% 以上或免除）
坦白                  减少 20% 以下
当庭自愿认罪          减少 10% 以下
一般立功              减少 20% 以下
重大立功              减少 20%-50%
累犯                  增加 10%-40%，一般不少于 3 个月
有前科                增加 10% 以下
退赃退赔              减少 30% 以下
赔偿并取得谅解        减少 40% 以下
刑事和解              减少 50% 以下
```

一个「自首减 45%」的判决，不需要任何法律知识就能判定越界——**它是一条 range 约束**。
今天没有任何系统在写入那一刻拦住它。

## 二、传统方案实测有多差

### 2.1 接了权威法律库的商用 AI，仍有六分之一以上答错

Stanford HAI / RegLab 的对照评测（*AI on Trial*）：

| 产品 | 错误率 |
|---|---|
| Lexis+ AI | > 17% |
| Ask Practical Law AI | > 17% |
| Westlaw AI-Assisted Research | > 34% |

错误分两类：**描述错法律**，以及**法律描述对了但引的来源不支持该主张**。
研究者特别点名后者更危险——来源看起来权威，用户反而更信。

> 这个数字是本次评估最重要的外部事实：**这三家都接了自家的权威全文库**。
> 也就是说，把正确的法条喂给模型，并不能阻止模型在输出侧写错。
> **RAG 解决的是「找得到」，不解决「说得对」。**

### 2.2 规则引擎：对，但贵，且规则与条文没有绑定

上海「206」刑事案件智能辅助办案系统（上海公检法 + 科大讯飞）做的正是证据标准指引、单一证据校验、证据链完整性校验、类案推送。方向完全正确，代价是：

- 按罪名逐个建规则，全国口径覆盖到 102 个罪名，早期版本只有 7 类 18 个罪名
- 规则是硬编码的领域知识，**规则与它所依据的条文之间没有可追溯的绑定**——条文修订后无从知道哪些规则失效
- 只在特定诉讼阶段介入，不覆盖文书生成

### 2.3 文书智能纠错：事后体检，不是写入门禁

各地法院在用的裁判文书智能纠错（如青海高院委托聚法科技对 32 万余份文书做「云体检」），检查项含错别字、格式、部分法理逻辑矛盾。它是**出稿之后扫一遍**，而不是**不合规就不许落盘**。差别在于：体检发现问题时，错误已经写进文书；门禁则让错误从来没有存在过。

### 2.4 GitHub 格局：三条路线，全部绕开了「办案过程的状态」

| 路线 | 代表 | 在做什么 | 缺口 |
|---|---|---|---|
| **训练更懂法的模型** | ChatLaw 7.5k★、LexiLaw 1.0k★、DISC-LawLLM 946★、HanFei 131★ | 法律语料微调 | 全部押在模型侧。**没有一个做输出侧校验**——模型说得越流利，错得越像真的 |
| **引注解析** | eyecite 264★、unitedstates/citation 251★、citeurl 44★ | 从文本里认出引用、转成链接 | 只解析不判定。能把 "410 U.S. 113" 变成链接，不检查它是否支持该命题、是否已被推翻 |
| **法律形式化** | Catala 2.4k★、Akoma Ntoso（OASIS）、LegalRuleML（OASIS）、ELI/ECLI | 给条文稳定 ID（Akoma Ntoso）、表达可废止规则（LegalRuleML）、把法条编译成可执行代码并与原文双向绑定（Catala） | **建模的是「法律」，不是「这个案子」**。门槛极高：Catala 需要法律专家与 PL 专家结对 |

**必须诚实承认**：「给法条稳定 ID」「把法律规则形式化」「把结论绑回条文原文」这三件事，
Akoma Ntoso、LegalRuleML、Catala 早就做了，而且比本象成熟得多。本象不能主张这些是自己的发明。

**空位在别处**：没有任何一个项目在跟踪**一个具体案件在办理过程中的世界状态**——
此刻认定了哪些事实、哪些情节已被采信、基准刑现在是多少、这个数字是谁在哪一步基于哪条改的。
Catala 能告诉你「法律怎么算」，它不知道**本案走到哪一步了**。这两件事互补，不冲突。

## 三、把本象的十条原则逐条落到法律场景

本象协议 v0.1 的十条设计原则（docs/03 第一节）没有一条是为法律写的，
但它们全部是从「状态在长流程里会腐坏」这一个问题上撞出来的。判决书是同一个问题的高代价版本。

| 原则 | 法律场景的对应物 | 治什么病 |
|---|---|---|
| **3 原文是本源，摘要是投影** | **法条原文是本源，AI 对法条的转述是投影，无权覆盖**。AI 输出的是条文 **ID**，运行时绑定真实文本（Flint 原则：不重新输出大型载荷） | **直接对治 §2.1 的 misgrounded citation**。AI 物理上无法伪造一条法条——它输出 ID，ID 不存在当场拒绝。这是与 RAG 的根本分野：RAG 让 AI **抄文本**，本象让 AI **引 ID** |
| **4 推断与事实分离** | 「本院认为」的每一句，要么挂 `evidence:`，要么标 `status: inference` + 置信度 | 自由心证与证据认定混写 |
| **5 每个状态都有来源** | 释法说理的机器化：任何字段都能追到产生它的事件 | 「有据可查」的字面实现 |
| **6 派生优先于存储，禁双份账本** | 涉案金额只存一处，「认定事实」段、「本院认为」段、判决主文三处都是**投影** | **判决书前后矛盾的根治**。本象是在 ShadowBench-W 里撞出这条的——钥匙同时记在人和物两处，转手后前持有人手里还留着一把。判决书里同一个数字写三遍，是同一个 bug 的更贵版本（可构成再审/补正事由） |
| **7 ID 必须自带归一化层** | 《刑法》第二百六十四条 / 刑法264 / 《中华人民共和国刑法》第264条 必须归一化 | 本象已为这条付过学费：模型把 `char:zhao-qi` 写成 `zhao-qi`，5 章正文全部作废。法条别名比人名别名更泛滥 |
| **8 校验器必须区分「拒绝」与「完成」** | 一个把所有草稿都打回的纠错系统，在「差错率」上永远完美 | 本象臂曾因全被拒绝产出零字，错误率 0.000，在只比错误率的判定下「赢」了裸模型 |
| **9 管住状态管不住文字，两层分别把关** | 量刑数字全对，说理段照样可能胡说 | 本象出现过状态字段全对、正文却把关键物品写在错人手上。把「正文对照状态」的确定性门禁接进去后，三次运行错误数从 1/6/3 降为 **0/0/0**。这个机制可直接搬到「说理段提到的每个数字必须等于状态字段」 |
| **10 系统可以拒绝，但不能沉默** | 校验不过要给法官一份可接手的稿 + 标注待复核 | **法律场景是硬需求**：法官有审限，卡死等于不可用。这正是舟舱（人类确认层）的位置 |

### 影核协议（ActionParity）在法律场景的位置

「一个语义动作，多个执行器」在这里不是理论：

| 语义动作 | 执行器 | 前置条件 / 约束 | 证据产物 |
|---|---|---|---|
| `retrieve_similar_cases` | 裁判文书网 / 法信 / 北大法宝 / 本院内网库 | 按 法发〔2020〕24号 的优先级顺序路由与回退 | **检索报告自动生成并随案归档**——指导意见本来就要求归档，今天靠人贴 |
| `apply_sentencing_factor(自首, -35%)` | 量刑计算器 | 前置：`factor:自首.status == 认定`；参数落在 法发〔2021〕21号 的法定区间 | `history.jsonl` 里一条带 basis 的 state_change |
| `cite(law:刑法/264, 裁判依据)` | 条文库 | 前置：该条在**裁判时点**有效 ∧ 该条类型在本案型可作裁判依据 | 引用记录 |

三条都在**执行前**判定，而不是**输出后**扫描。这是影核和纠错系统的分界线。

## 四、一个可跑的法律方言（照 CAD 方言的模子）

CAD 方言最有说服力的地方不是它抓到了什么，而是**它没有给核心加一行代码**——
把图层编进 ID 之后，「门窗层构件数必须等于标注层编号数」就是一条通配 `count` 约束。

法律方言可以用同一个手法。核心现有的十个谓词是
`equals / not_equals / contains / not_contains / range / in / exists / unique / count / unchanged`，
外加 `对象:*` 通配展开、悬空引用检查、双份账本检查、模型偏差率、`why` 证据链。

### 4.1 ID 设计：把判定所需的分类编进 ID

```
law:刑法/264              规范性文件——法律
interp:法释2013-8/3       ——司法解释
adminreg:行政法规/xxx      ——行政法规
rule:公安部规定/3          ——规章（刑民案件不得作裁判依据）
case:2026-沪0101-刑初-123 本案
fact:F-02                 认定事实
evidence:E-03             证据
factor:自首               量刑情节
cite:裁判依据/07          引用（裁判依据位）
cite:说理/03              引用（说理位）
```

### 4.2 约束清单：哪些现有谓词直接够用

| 要判的事 | 谓词 | 是否需要给核心加代码 |
|---|---|---|
| 每个量刑情节必须附证据 | `exists` on `factor:*.basis` | 否 |
| 引用的对象必须存在 | 悬空引用检查（已有） | 否 |
| 裁判依据只能是法律/司法解释 | 导入时把被引对象的类别物化成 `cite:裁判依据/*.target_kind`，再 `in {law, interp}` | 否——**这就是「把图层编进 ID」的同款技巧** |
| 法条在裁判时点有效 | 导入时派生 `cite:*.effective_at_judgment`，再 `equals true` | 否——同款 |
| 调节比例落在法定区间 | `range` on `factor:自首.ratio` (max 0.40) | 否；20 条常见情节一次性写成数据 |
| 情节编号不得重复 | `unique` | 否 |
| 认定事实数 = 说理段论及数 | `count` + `equals_count_of` | 否 |
| 同一数字不得两处记账 | 双份账本检查（已有） | 否 |
| 说理段的每个数字必须等于状态字段 | **正文对照门禁**——ShadowBench-W 里实现过，但在实验臂里，不在核心 | **要在方言里自己写**（对应 CAD 的 `import.mjs`） |

**九条里八条不用动核心。** 这是这个方案最强的论据，也是它跟「再训一个法律大模型」的根本区别：
法律知识进的是**数据**（条文库 + 约束表），不是**权重**，条文修订时改数据即可，不必重训。

同一份案卷改判 12 个月（超出指导意见给的 20% 幅度），提交编译器当场拒绝：

| **B 引用真的支持该命题** | ⚠️ **只解决一半**：保证条文真实、有效、类型合规，AI 物理上无法伪造一条法条；**不能**判断它是否支持那句话 |
| **C 认定到结论链条完整** | ✅ 情节必须挂证据、认定某情节必须引对应条文、不得重复评价 |
| **D 数字可复算** | ✅ 区间、复算、20% 幅度、正文对照，四条全覆盖 |

**诚实的一句话**：把 Stanford 那 17%–34% 里的错误从**四类压到一类**，剩下那一类交给人。
这不是「AI 不会再错」，是「AI 错在哪一类，现在是确定的」。

---

## 五、不主张什么（红线）

1. **本象不判案，也不该判案。** 法发〔2022〕33号《关于规范和加强人工智能司法应用的意见》确立辅助审判原则——AI 辅助结果只能作参考，不得代替法官裁判。本象管的是**结论到依据的可追溯性**，不是**结论对不对**。定位只能是「辅助 + 留痕」，不能是「生成 + 交付」。
2. **§4.4 那张表量的是「门禁能力」，不是「本象比 RAG 好多少」。** 检出率 83.3%、假阳性 0，说明的是确定性约束抓得住哪些缺陷；它**没有**说明本象臂生成的判决书比 RAG 臂更好。后者要跑 ShadowBench-L（§六）。而 92.5% / 98.9% 出自 ShadowBench-W 的叙事状态追踪，更不能搬。任何对外表述都必须说清这三者的区别，否则就是本象一贯反对的那种主张。
3. **Token 更贵**（qwen +25%，带长思维链的 deepseek +149%）。法律场景对此不敏感（一份判决的人力成本远高于 token），但不能不说。
4. **条文库的维护是脏活，本象不消灭它。** 时间效力、修正案、司法解释废止关系——本象只是把它变成一个有 provenance 的对象库，仍然要有人维护。这是整个方案最大的隐性成本。
5. **B 类问题（引用是否真的支持该命题）只解决了一半。** 本象能保证引用的条文**真实存在、有效、类型合规**，能保证 AI 无法凭空造条文。**它不能自动判断这条真的支持那句话**——那需要人，或需要 Catala 式的形式化。诚实的说法是：把 §2.1 的错误从「四类」压到「一类」，剩下那一类交给舟舱。

## 六、下一步：ShadowBench-L（可证伪的实验）

要把 §三 的结构论证变成结论，需要一个和 ShadowBench-W 同样规格的对照实验：

- **语料**：公开裁判文书（刑事、有量刑情节、有明确法条引用）N ≥ 30 份，构造成世界规格
- **任务**：给定认定事实与证据，生成「本院认为」段 + 量刑计算 + 法条引用
- **三臂对照**：本象 / 裸模型 / 向量 RAG（与 W 保持一致，可比）
- **判分维度**（必须先定，防止事后挑指标）：
  1. 引用真实性（引的条文是否存在）
  2. 引用可引性（是否符合 法释〔2009〕14号 的类型白名单）
  3. 量刑可复算（每步是否落在法定区间，加总是否等于宣告刑）
  4. 文书内一致性（同一数字在各段是否相同）
  5. 完成率（照原则 8：先要求完成，再比质量）
- **预注册反例**：如果本象臂在维度 1、2、3 上不显著优于 RAG 臂，本方案作废——
  因为这三条正是「结构而非模型」应该赢的地方，赢不了就说明论证是错的。

**判分器已经现成了**：§4.3 那 24 条约束就是判分维度 1–4 的机器实现，
`adapters/law/selftest.mjs` 里的缺陷目录就是判分模板。维度 1 是 `status: not-found`，
维度 2 是 `status: not-citable`，维度 3 是 `range` + 重放，维度 4 是 `mention` 对照。
**判分器不需要法律知识，只需要条文库**——这一条已经跑通并验证（变异检查 9/9）。

剩下的三件事：

1. **扩条文库**：`lawdb.json` 现在只有 20 条样本。要跑真实验得覆盖盗窃、诈骗、危险驾驶等常见罪名的完整条文与司法解释，含效力区间。这是脏活，但一次性。
2. **造语料**：N ≥ 30 份判决书 fixture（含量刑评议表）。**这是典型的批量粗活，交给本地廉价通道（`bl` / `hermes`）按模板生成，不占主会话 token**；判分维度与约束表已固定，生成质量的下限由门禁自己兜住。
3. **接三条对照臂**：复用 `benchmark/shadowbench-w/arms/lib/model.mjs` 的 provider 抽象，与 W 保持可比。
