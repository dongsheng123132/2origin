## 一、ClawHub（clawhub.ai）——国际

### 平台性质
- OpenClaw 的**官方 skill/plugin 注册表**（类似 npm 之于 Node）。
- 跟踪 semver 版本、latest 标签、changelog、文件、下载量、star、安全扫描摘要。
- 站点：clawhub.ai（国内直连超时，需代理；有镜像 clawhubcn.com / cn.clawhub-mirror.com）。

### 发布流程（官方文档实读）
```bash
npm i -g clawhub          # 安装 CLI
clawhub login             # 浏览器跳 GitHub 登录，本地回调存 token
clawhub whoami            # 验证
clawhub skill publish ./my-skill --slug my-skill --name "My Skill"
# 新 skill 自动从 1.0.0 起；再发布自动 patch（1.0.1）；--version 可显式指定
# --owner <handle> 发到组织；省略则发到个人账号
```
- 校验失败不发布（metadata/name/version/files/source 逐项验证）。
- 发布后自动安全扫描，扫描完成前不进正常安装/下载面。
- 支持 GitHub Action 自动化：`openclaw/clawhub/.github/workflows/skill-publish.yml@main`
  （配 `secrets.CLAWHUB_TOKEN`，`dry_run: true` 可预览）。
- 无头环境：`clawhub login --token clh_...`（网页 UI 建 token）或 `clawhub login --device`。
- Windows token 存 `%APPDATA%\clawhub\config.json`。
- 命名空间保护：插件 `@owner/package` 的 scope 必须匹配发布者；org 认领走 issue 流程。

### Skill 格式要求
- 目录 = 一个 skill；必含 `SKILL.md`（Markdown + 可选 YAML frontmatter）。
- frontmatter 必填：`name`（1-64 位小写字母/数字/连字符，应与目录名一致）、
  `description`（作为 UI/搜索的摘要）、`version`。
- 运行时元数据放 `metadata.openclaw`（声明 runtime 需求、权限）。
- 支持 `.clawhubignore` / `.gitignore` 排除文件。

### 与本象的关系
- OpenClaw 是 agent 编排器，ClawHub 是它的 skill 分发层。
- 本象协议不做第四个编排器，做对象状态一致性层——skill 发布正好把
  OriginWriter / Shadow Memory / office 方言推到 agent 生态的安装面。

## 二、SkillHub（skillhub.cn）——中文（腾讯官方）

### 平台性质
- 「专为中国用户优化的 AI Skills 社区」，10.7 万 skills。
- **腾讯背景确认**：备案粤B2-20090059-4038、反馈邮箱 skillhub_ipr@tencent.com、
  首页有微信小程序 AI 开发专区（微信小程序团队官方出品）、腾讯文档/腾讯会议/ima 官方 skill、
  底部友情链接指向 ClawHub——即腾讯在中文侧的 skill 分发布局。
- 特色：企业认证蓝V、AI 评分（4.5/5.0 示例）、安全扫描（科恩实验室/云鼎实验室双报告）、
  **内容指纹 + 数字签名**（用户可验证 skill 完整性——与本象「可验证的对象」同频）、
  下载 Zip 包安装、公开 API（api.skillhub.cn/api/skills）。

### 发布流程（页面实读）
- 点「发布 Skill」→ 弹登录：个人登录 / 团队登录（新功能）/ 微信 / 手机号。
- 需登录后才有发布表单（未登录被弹窗拦住，未深入发布页）。
- 发布后的 skill 详情页有：概述 / 文件 / 评论 / 版本历史 / 评测报告 / 效果预览。

### Skill 格式
- 示例 skill（find-skill-skillhub）共 15 个文件：`SKILL.md`（3.7KB）+ `references/` 支持文件。
- 即标准 Agent Skill 格式，与 Hermes skill 同构。

### 与本象的关系
- 中文发行主通道。本象的宣言、中文 skill（origin-writer 写作引擎等）在这里发，
  受众是中文 agent 用户，且腾讯系（腾讯文档/会议/ima）都在场，办公类 skill 有现成生态位。

## 四、商业化方向（三个候选，按可行性排序）

### 方向 A：百万字小说写作网站（最直接，已有引擎）
- **产品**：网站/CLI 提供「AI 写长篇」服务：用户给设定 → OriginWriter 建世界包 →
  逐章事务提交 → 状态自动维护（人物/伏笔/时间线）→ 输出可验证的连载。
- **卖点**（区别于市面 AI 写作工具）：
  1. **真长篇**：市面工具 5k-50k 字就崩（模型忘设定），本象引擎状态持久化 + 门禁，
     10 万-100 万字不穿帮——这是「上下文必炸」难题的产品化答案。
  2. **可验证**：每章状态变更留证据链，作者能查「这个设定什么时候定的、谁改的」。
  3. **伏笔图谱**：市面没有。埋了 40 章的伏笔到第 43 章回收，引擎帮你记着。
- **变现**：按字数订阅（¥/万字）、作者平台抽成、企业定制（游戏世界观/剧本）。
- **可行性**：引擎已有（26 项自测），缺的是 Web 壳（用户设定界面 + 连载阅读页 + 支付）。

### 方向 B：无限长小说挑战（传播杠杆，成本低收益高）
- **形式**：一个公开的「世界最长 AI 小说」项目——单一世界包，AI 持续续写，
  每章过门禁后发布，世界状态公开可查（伏笔图谱、人物档案、时间线都是活的）。
- **卖点**：这是 ShadowBench-W 从基准走向大众的桥——「别人做 5k 字就穿帮的题，
  我们跑了 100 万字且状态可验证」。吉尼斯/记录类传播自带流量。
- **执行**：GitHub repo（世界包 + 每章正文 + 状态快照公开）+ 官网（hequbing.com 博客连载）+
  X/公众号日更。**世界最长小说**已有先例（Agence France-Presse 2019 年宣布 200 万字小说，
  实际是人类集体创作）；「AI 以事务机制续写且状态可验证」这个定语无人占位。
- **可行性**：引擎已能跑（demo.mjs 演示了 ch11 提交），需要的是持续写 + 公开页。
- **注意**：ShadownBench-W 已有「不能无损压缩百万字」的路线纪律——公开挑战正好是
  这个论点的实证（状态存本象包，正文存分片，两者分离）。

### 方向 C：企业文档合规底座（借 office 方言，B 端）
- 海事局红头文件 409 个结构对象已验证（6章/77条/16表/59勾选），
  政府/国企的公文、合同、规章是「要可验证、可追溯、可审计」的场景。
- 产品形态：文档 → 本象包 → 版本差异追踪 → 条款级引用，卖给合规/档案系统集成商。
- 比 A/B 慢，但客单价高。可做 A/B 跑出影响力后的第二曲线。
