# 全球格局调研与评估（2026-08-02）

> 三个并行调研线（记忆系统 / 长篇写作 / 上下文压缩与编译）的实时情报快照 + 综合评估。
> 情报为 2026 年 8 月时点数据，会过期；评估结论供 MVP 决策（docs/06）参考。

---

## 综合评估（先看这个）

### 一、「全球是不是就缺这个」——精确答案

**不缺的（红海，别进）：**

- 「个性化记忆层」：对话事实抽取 + topK 检索，mem0（47.5k★，$24M A轮）、Supermemory（~$29M）、memobase 等十余家
- 时序知识图谱存储：Zep/Graphiti、cognee（$7.5M）已卡位
- 读侧 QA 跑分：LongMemEval 已卷到 94.87%（Mastra）
- Lossy 文本压缩：LLMLingua 成熟但无人做成平台

**缺的（四个空档，全部有据）：**

| 空档 | 现状证据 |
|---|---|
| ① 写侧事务语义的**产品化**（确定性校验器把关的状态更新，而非 LLM 自裁决增删改） | 产品层无人做；学术 2026 上半年密集收敛（MemTX、Cordon、Eywa、SagaLLM）但全是论文原型，无 funded 公司以此为核心 |
| ② 任务感知 + 预算约束的上下文**编译**（不是事后压缩/GC） | 头部 Agent 产品（Claude Code/Codex/Gemini CLI）全是破坏性摘要范式，痛点从「爆炸」变成「compacted stupid」；碎片实现只在代码域小项目 |
| ③ 跨域统一协议（输入投影 + 输出事务的双向闭环） | 输入侧与输出侧分属两个互不相识的社区；Flint 双向但只限图表；天命闭环但是单机应用；ICML 2026 position paper 直指「missing runtime」 |
| ④ **写侧评测基准** | 所有主流记忆基准（LoCoMo/LongMemEval/LifeBench）本质是读侧 QA，无一考核写回正确性、约束违反检测、证据链质量 |

### 二、「是不是最佳解法」——方向被三路独立证据收敛验证

- **学术同构**：MemTX（arXiv 2607.23929）的「快照隔离事务 + validate-and-commit + evidence/provenance/validity + 信念级联修复」与本象写回主张几乎逐条对应；Cordon（arXiv 2606.17573）的 prepare/validate/commit 三段式语义事务 ≈ 我们的 Commit Compiler
- **民间独立发明**：国产开源「天命」（tianming-novel-ai-writer，369★）在小说域独立做全了「状态机 + 变更回写 + 门禁校验 + 切片上下文」四件套
- **学界点名空白**：ICML 2026 position paper——MCP/A2A 解决连接，state/memory/budget/guardrail 无人交付可移植实现，「如同 OS 出现前的计算机」

这既是好消息（方向对，不是妄想）也是坏消息（**不是独创，是赛跑**）。记忆线调研判断：窗口约 12-18 个月，之后会有 funded 玩家进场。

### 三、选题建议（旗舰测试怎么选）

| 候选选题 | 判断 |
|---|---|
| 长对话恢复（读侧） | 痛感强但已红海，LongMemEval 读侧无空间；**写侧**变体有空间：「断线重连后回答我们决定过什么+为什么+证据在哪」——无现成基准，可自定义 |
| **百万字小说连续性（推荐旗舰）** | 公开实测完全空白（现有实测止步 1-10 万字，ConStory-Bench 仅 1 万词）；CED 指标（每万词一致性错误数）现成可用；故事性强、易传播；华东师大百万字案例自评 61 分、裸模连贯极限约 3 万字——对照组现成 |
| 100页PPT审阅 | 依赖 Office 全链路，工程量大；且视觉 atlas 层被 VTCBench 泼冷水（可读≠可推理），不宜作首战 |

**推广策略修正**：发布物不应是「又一个记忆层/写作工具」，而是**基准 + 数据 + 协议**三件套——因为写侧基准现在不存在，先定义者拿标准制定权。名字可以叫 OriginBench-W（写侧）。

### 四、必须正视的四个风险

1. **命名撞车**：Origin Protocol 是知名加密货币项目（OGN）。英文名必须避让。→ **已解决（2026-08-02）**：英文品牌定为 **Benxiang**（GitHub 无撞车，「本」自带 origin 义，典出「立象以尽意」）；Origin IR 保留为技术术语；OriginX 方案否决（撞 xOGN 与 Fabric.js originX）。
2. **「加结构反而更差」警告**：ConStory-Bench 实测多步 agent 写作系统（SuperWriter CED 0.674、DOME 1.033）**显著差于**顶级裸模型（GPT-5-Reasoning 0.113）。加了状态管理≠更好，做错了更差。我们的 Benchmark 第一步必须先证明自己不是 SuperWriter 第二——这是 ShadowBench 的第一道生死题。
3. **厂商吸收**：Anthropic 服务端 compaction 三个月从无到 GA。输入侧压缩最容易被平台内建；写侧事务+证据链+跨域协议最难被吸收——护城河应压在写侧。
4. **先行者对位**：小说域「天命」已做全闭环（无 evidence/assertions/协议化/百万字实证）。对位策略应是致敬+超越（协议化、可互操作、公开基准），不是假装它不存在。

### 五、对 docs/06 路线图的修订建议（待用户拍板）

- 旗舰公开测试：**百万字小说连续性**（Story 方言先行），用 CED 指标 + 自建写侧任务
- 标准制定权抓手：**写侧记忆基准**（Memory 方言的差异化不在读侧跑分）
- 两者共享同一套核心（状态机 + 语义事务 + 证据链 + 上下文编译），做一次核心、赢两个战场
- PPT/Office 线降级为 Phase 3+（等 atlas 层价值在窄场景验证后再上）

**2025-2026 新冒头**：Hindsight（Vectorize，LongMemEval 91.4% 首破90）；Supermemory（~$29M）；Mastra Observational Memory（LongMemEval 94.87% 历史最高，双后台 agent 压缩观察日志）；MIRIX（六类记忆，LoCoMo 85.4%）。

**学术直接命中区**（均为 2026 上半年论文原型，无产品）：
- **MemTX**（arXiv 2607.23929）：快照隔离事务 + validate-and-commit + evidence/permissions/provenance/validity + 撤回信念级联修复——与本象写回主张几乎同构
- **Eywa**（arXiv 2605.30771）：provenance-grounded 记忆，区分观测 vs 推导
- SagaLLM（多 agent 事务保证）、MemArchitect（策略治理层）

**基准现状**：LoCoMo（~300轮，被广泛质疑，厂商互撕现场）；LongMemEval（500题/115k-1.5M token：Mastra 94.87 > Hindsight 91.4 > MemOS 89.2）；2026 新基准 LifeBench（SOTA 全体崩盘：MemOS 55.22%）、LoCoMo-Plus、BEAM。**全部基准是读侧 QA，无一测写回正确性/约束违反/矛盾修复/证据链/预算效率。**

**结论**：最拥挤=事实抽取+topK 个性化记忆层；最空=写侧三件套。「事务式写回+约束校验+证据链」组合产品层无人做，学界已收敛，窗口 12-18 个月。

## 附录 C：上下文压缩与编译赛道原始报告

1. **视觉-文本压缩**：DeepSeek-OCR 2（2026-01，OmniDocBench 91.09%，HF 月下载 220 万+）；Glyph 有效压缩 3.3×；**VTCBench 泼冷水：多数 VLM 能 OCR 但压缩下长程推理明显退化（「看得清、想不通」）**；产品化只有 pxpipe（把 Claude Code 上下文渲染成 PNG，省 59-70%，自认「gist tier 非无损」）；OpenAI/Google 均未原生跟进。
2. **文本压缩**：LLMLingua-2 仍是 lossy 压缩事实标准（生产压缩率 4-10×），成熟但无人做成平台。
3. **上下文工程框架**：ACE（Stanford，自进化 playbook，非按任务/预算编译）；Anthropic 已产品化 context editing / memory tool / 服务端 compaction（compact_20260112 beta）——**全是「事后垃圾回收」，不是「事前投影编译」**；最接近输入侧主张的是 jcodemunch-mcp 和 budget-aware-mcp 两个代码域小项目。
4. **中间表示/协议**：Flint 2.9k★、2026-07 连发三版，**仍只做图表**；ICML 2026 position paper 指「missing runtime」（state/memory/budget/guardrail 无可移植实现）；输出侧同构论文 Cordon（prepare/validate/commit 语义事务）+ SagaLLM + ESAA，均无产品化；A2A v1.0/AGNTCY 管通信不管世界状态；MCP 生态无「context compiler」类 server。
5. **头部 Agent 产品**：Claude Code 四五级压缩流水线、Codex 服务端加密 compaction、Gemini CLI 两遍自校验摘要——全部是破坏性摘要范式，**痛点从「爆炸」进化为「compacted stupid」（压缩后变笨），痛点仍在且更清晰**。

**结论**：「任务自适应+预算感知编译」定位没人占；「统一 IR+双向编译」更没人做全（输入投影与输出事务两个社区互不相识）；最大差异化=把 Cordon 式事务+Graphiti 式结构+预算编译+atlas 焊成一个协议；最大风险=(a)厂商吸收（Anthropic compaction 3 个月 GA）(b)VTCBench 对视觉层的质疑 (c)通用 IR「什么都表示=什么都表示不好」老病 (d)Origin Protocol 撞名加密货币 OGN。
