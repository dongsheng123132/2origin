# 《规则怪谈·无限层》—— 无限构建小说题材提案

> 2026-08-06 · 本会话提案（与另一 Hermes 进程的提案并列，供对比拍板）
> 定位：世界最长 AI 小说挑战 · GitHub 共创 · 本象协议状态可验证
> 提案人：Hermes（本会话）

## 0. 一句话

近未来，地球上空开始随机降临"层"——异常空间。每个层都有一套**规则**。
遵守规则，活；违反规则，被**抹除**（连存在过的痕迹一起消失）。
主角是专职"守规人"：每章进入一个层，在死亡规则下救出被困者，
并逐渐发现——所有层的规则里，藏着同一个词。

## 1. 题材判断：为什么现在火，未来一二年还火

| 依据 | 说明 |

## 2. 为什么适合 GitHub 共创（关键差异化）

别的题材（克苏鲁/权谋/传统玄幻）共创门槛高：不懂主线就插不上手。
规则怪谈的共创门槛是**所有题材里最低的**，而且四种参与方式由浅到深：

1. **提交层设定**（门槛最低）：任何人都可以按模板写一个新层的名称+3-5 条规则+怪物+物品，开 Issue 提交。官方审核合入 spec，下一章就可能是你设计的层。
2. **规则抓虫**（参与感最强）：规则是对象、是可验证的。读者/贡献者可以检查"第 N 章主角有没有违反第 M 条规则"——抓到违反规则的 bug 就是为 canon 做贡献，进贡献榜。**"抓虫即共创"是本题材独有**：别的小说没法验证，这部可以。
3. **周征集投票**：每周官方开 Issue 征集候选层，GitHub Reactions 投票，得票最高者下周进正文。
4. **番外合入**：贡献者写角色番外（守规人出任务间隙的小故事），符合 canon（不违反已建立规则/状态）的合入仓库，作者署名进 provenance。

贡献可追踪：origin 包的 provenance by 字段记录每个合入贡献者的 GitHub id——"共创"不是口号，是账本。

## 3. 世界观设定（六个核心概念）

- **层（Layer）**：随机降临的异常空间，入口出现时会有 3 分钟"降临预警"。每个层一套规则，规则数量 3-7 条。
- **规则（Rule）**：层的宪法。分**明规则**（入口处可读，如"收银台只收现金"）与**暗规则**（藏在行为里，不遵守才会发现，如"凌晨 3:00 后橱窗会换"）。明规则违反即抹除；暗规则违反轻则受伤、重则抹除。
- **抹除（Erase）**：违反明规则的下场。不是死亡——是存在痕迹一起消失：认识你的人不再记得你，你留下的文字照片全部消失。**抹除是比死亡更重的代价**（死亡至少有人哀悼，抹除没有）。
- **守规人（Rulekeeper）**：被"管理局"招募、有资格进入层的职业。普通人进层九死一生，守规人因受过训练（背规则、带装备、记暗规则）生存率高。主角是第 7 期守规人。
- **管理局（Bureau）**：管理层的半官方机构，负责预警、救援、规则编目。内部对层的来源有三种学说，互相吵了十年。局长从未露面。
- **大秘密**：所有层的规则里藏着同一个词（如"镜子"或"第七"）。主角在层 10 首次察觉，层 20 确认这不是巧合——层是被"放置"的，而放置者认识他。

## 4. 对象模型（origin 包）

```text
layer:<id>      层      { name, danger_level(1-5), status(open/cleared/sealed), entry_chapter }
rule:<id>       规则    { text, kind(明/暗), layer, enforcement(machine_check), discovered_chapter, contributed_by }
character:<id>  角色    { name, san, status(alive/erased/missing), current_layer, inventory[] }
item:<id>       物品    { name, layer, effect, durability }
entity:<id>     存在    { name, layer, behavior, weakness(暗规则线索) }
hook:<id>       伏笔    { summary, layer, status(planted/resolved), payoff_chapter }
```

- 伏笔 = 层间隐藏联系（同一个词反复出现、同一个符号、同一个人在不同层出现）
- 状态变更：主角 SAN 值、物品得失、角色生死、层的 cleared 状态——每章一个事务
- 禁区（门禁拒绝）：主角抹除/死亡、核心配角抹除、已发现明规则被违反、层状态回退

## 5. 规则即约束（技术卖点，别的题材给不了）

怪谈的"规则"与本象协议的"约束"是**同构的**——这是选题最狠的一点：

- 层的明规则 → origin 包 constraints（machine_check 谓词：equals / not_contains）
- 每章写作时，主角"当前已知规则集"进世界状态投影，模型写作必须遵守
- 违反已建立规则 → 门禁拒绝落盘（约束违反），跟故事里违反规则被抹除同构
- 读者可验证：clone 仓库 → `origin-office` 同款 verify → "第 8 章主角是否违反第 3 条规则"机器可查

对外叙事一句话："**一部规则可以被机器验证的小说**"——全球没有第二部。
这个定语同时服务：无限长小说挑战（传播）、本象协议展示（技术）、读者信任（可验证）。

| 04 | 地铁末班车 | 末班车只停 7 站；空位不能坐；报站声不对时下一站下车 |
| 05 | 镜面医院 | 病历上的名字不能念出来；走廊护士不回答"几点"；探视时间外敲门不要开 |
| 06 | 旧校舍 | 上课铃响前必须进教室；黑板上的名字不能擦；晚上 10 点后不要看厕所镜子 |
| 07 | 环形超市 | 购物车不能推过收银线；广播"即将打烊"后不要结账；出口只在你买过东西后存在 |
| 08 | 无灯酒店 | 房卡不亮请去前台换；不要乘坐显示"满员"的电梯；凌晨 4 点的敲门来自 404 |

暗规则示例（层 01）：店里的猫会数人数，人数不对时它盯着你——这条不算明规则，但第一次违反只是受伤，第二次才是抹除。暗规则在正文里由主角自己发现，是"伏笔+状态"双重的展示。

## 7. 与备选题材对比

| 维度 | 规则怪谈·无限层 | 无限流克苏鲁 | 调查员档案 | 王朝权谋 |
|---|---|---|---|---|
| 共创门槛 | ★最低（层设定模板化） | 高（需懂副本体系） | 中 | 高（需懂人物关系） |
