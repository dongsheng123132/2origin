| Token（输入+输出） | 43303 | **29333** | A3 省 32% |
| 耗时 | 345s | **256s** | A3 快 26% |

**Gate 0 判定：未通过。** 按预定规则，停止扩大规模，回头改架构——不允许用「规模再大点就好了」搪塞。

### 结果是分裂的，这比单纯输赢有信息量

- **状态层完胜**：A3 状态 100% 正确且每个字段可追溯来源；A0 把黑钥匙交到了**叛徒白遥**手上（任务目标是交给林峥），且完全无法报告伏笔状态。
- **原文层惨败**：A3 的 CED 是 A0 的 7 倍。

### 根因（已定位，非模型问题）

A3 的 `run()` 漏接了 `corpusTail` 参数，导致**它在从未读过前文正文的情况下续写**——只有结构化状态，没有一个字的原文。

协议文档写的是三层投影：**图负责找、结构负责懂、原文负责准**（[docs/02 §5](../../docs/02-概念体系.md)）。我在 A3 里只接通了「结构」一层，「原文」层压根没通电。所以原文层面的错误反超裸模型，是实现不完整，不是设计被证伪。

### 一个值得单独记下的观察

A3 的上下文里**明文列着**「铜铃鸣响时方圆十里禽鸟尽飞」这条规则，仍违反 3 次；A0 从未见过这条规则，却 0 违反——因为它读过第 3 章原文，从行文里学会了这个惯例。

> **结构化明示的规则，未必比原文里的隐含示范更管用。**

这条对协议是真提醒：规则清单不能替代原文样例，三层投影缺一不可。这也正是设立本基准的意义——没有它，这个判断只会停留在直觉层面。

## Run #3 · 2026-08-02 · Gate 0 仍未通过，但暴露了基准本身的问题

修正：A3 接通精确载荷层（`corpusTail` → `recentText`，按预算截取）。其余不变，A0 沿用 Run #2 数据。

| | A0（Run #2） | A3 Run #2（无原文层） | A3 Run #3（有原文层） |
|---|---|---|---|
| 产出 | 21058 字 | 14941 字 | 16415 字 |
| **CED** | **0.475** | 3.346 | 1.218 |
| W3 状态准确率 | 75.0% | 100% | 87.5% |
| 证据可追溯率 | 无此能力 | 100% | 100% |
| Token | 43303 | 29333 | 35600 |

接通原文层让 CED 从 3.346 降到 1.218（**证实根因判断正确**），但仍高于 A0 的 0.475。

### 但这里必须诚实：这个差距没有统计意义

CED 1.218 = 16415 字里 **2 处**错误；CED 0.475 = 21058 字里 **1 处**错误。**一起对两起，是噪声，不是结论。**

两次 A3 之间的波动也印证了这点：W3 从 100% 掉到 87.5%（黑钥匙这次没转手成功），CED 却大幅改善。单次运行无法区分「架构差异」与「随机波动」。

### 基准设计的缺陷（比实验结果更重要的发现）

**确定性通道只能抓到极小一部分错误**——时辰、左手、保管链、铃响、赵七生死这五类规则可判的事件，在 2 万字里本就罕见。而 A3 的核心主张恰恰在确定性通道**测不到**的地方：知识越界（林峥是否隐隐察觉了白遥的秘密）、语气暗示、伏笔误收。

所以当前的 Gate 0 实际在用一把只能量粗粒度的尺，去测一个主要作用于细粒度的系统。

三条修正，缺一不可：

1. **接入语义通道**——知识越界才是主战场，双模型交叉 + 分歧人工裁决
2. **多次重复取均值**——单次运行的方差已被证实大到能翻转结论
3. **必要时扩到 M 级**——2 万字里的可判事件太少，样本量不足

**在这三条落地前，任何「A3 优于/劣于 A0」的说法都不成立**，包括本轮的「未通过」。Gate 0 的结论应改为：**判定条件尚不具备**。

### 顺带值得记的一条

好消息是 W3（状态回写正确性）在两次运行里都明显优于 A0（87.5%–100% vs 75%），且 A0 完全无法报告伏笔状态、还把黑钥匙交给了叛徒。**这个维度上确定性通道就够用，因为它比的是结构化状态而非文字**——这也侧面说明：W3 之所以是本基准最扎实的部分，正因为它不依赖文本判读。

## Run #4 · 2026-08-02 · 接入语义通道后重判（文本沿用，未重新生成）

语义通道 `eval/judge.mjs`：双模型交叉（hermes/deepseek + 百炼/qwen-plus），只采信双方一致指认，引用对不上原文的一律丢弃。

|---|---|---|
| 产出字数 | 21058 | 16415 |
| 确定性通道 CED | 0.475（1 处） | 1.218（2 处） |
| 语义通道 CED | 0.950（2 处） | 0.609（1 处） |
| **合计 CED** | **1.425** | 1.828 |
| **确认错误总数** | **3 处** | **3 处** |
| W3 状态准确率 | 75.0% | **87.5%** |
| 证据可追溯率 | 无此能力 | **100%** |
| Token | 43303 | **35600** |

### 最重要的发现：CED 这个指标在小样本下可以靠「多写字」刷低

两臂**各自都是 3 处确认错误**，完全相同。CED 之所以不同，纯粹因为 A0 多写了 4643 字：

```
A0： 3 ÷ 21058 × 10000 = 1.425
A3： 3 ÷ 16415 × 10000 = 1.828
```

也就是说，在错误数是个位数的量级上，**一个臂只要把正文写长就能降低 CED**。这不是模型能力差异，是指标的归一化伪影。ConStory-Bench 用 CED 是在 8k-10k 词的固定长度上，我们把它搬到「各臂自由发挥长度」的场景里，就引入了这个漏洞。

修正方向（待定）：按章归一化而非按字数、或对章节长度设硬上限、或直接比绝对错误数。

### 定量打平，但定性有差别

A0 的两处语义错误里，有一处踩的是**本任务最核心的禁区** `fz:betrayal-secret`：

> 「阿枝看见白遥，是你让她看见的……」——林峥明确知晓阿枝目击白遥之事，而阿枝从未告诉任何人，林峥更不应对白遥的秘密有任何认知。

A3 的那处是赵七说出了黑钥匙来历（他不该知道），属外围设定，未触碰核心禁区。

两臂在 W3 上都没完成任务目标：A0 把黑钥匙交到了**叛徒白遥**手上，A3 让钥匙留在赵七处没转手。前者更糟。

### 判官分歧严重，语义通道尚不能独立承重

| | hermes 判官 | 百炼判官 | 一致 |
|---|---|---|---|
| A3 | 1 处 | 17 处 | 1 |
| A0 | 5 处 | 16 处 | 2 |

一个保守到几乎不报，一个热心到把「伸手够刀鞘必然要用左手扶」这种推理都算成状态矛盾。**双模型交叉此刻起的是降噪作用，但两把尺子的刻度差了一个量级**，说明判官需要先校准（给定标注样本、统一严格度）才能让语义 CED 具备可比性。

### Gate 0 判定

仍为 **判定条件尚不具备**。三项前提在本轮完成了一项（语义通道已接入），剩两项：判官校准、多次重复。

在这些落地之前，唯一站得住的结论是：

> **W3（状态回写正确性）维度上，本象方案稳定优于裸模型，且成本更低；W1（正文一致性）维度上，现有实验无法区分二者。**

这恰好也是本项目最初的判断——写侧状态是空档，而这个空档确实是真的。

也就是说，提交编译器只校验「状态变更声明」，从不拿正文去对照状态。协议文档要求的「修改后必须通过的验证」我只做了一半：那些确定性规则只在**评分时**跑，没在**门禁时**跑。

> **管住状态管不住文字。** 结构化状态正确，不自动带来正文正确——这两层必须分别把关。

修正：把确定性规则接进提交编译器，正文违规直接退回重写（`prose-violation`）。这也正是协议一直承诺的「叠象验证 → 退回重写」闭环，此前只是没接上。

## Run #9 · 2026-08-02/03 · **Gate 0 通过**（10 对 10，置换检验 p=0.0121）

两臂各跑满 10 轮，跑完后用 `eval/rescore.mjs` 以当前规则统一重打分（正文已存盘，零 API 调用）——判分规则在实验期间被修补过，横向比较前必须先统一口径。重打分显示新旧分数完全一致，无口径漂移。

| | A0 裸模型（n=10） | A3 Benxiang（n=10） |
|---|---|---|
| **EPC 均值** | 0.54 | **0.16** |
| **EPC 中位** | 0.60 | **0.00** |
| 标准差 | 0.36 | 0.20 |
| 区间 | [0.00–1.40] | [0.00–0.40] |
| **W3 状态准确率** | 75.0%（十轮全同） | **93.8%** |
| 完成率 | 10/10 轮 5/5 章 | 10/10 轮 5/5 章 |
| Token 均值 | **42967** | 56747（+32%） |

**置换检验**（20000 次重排，无分布假设）：均值差 −0.38，**p = 0.0121 < 0.05**。

> **Gate 0：通过。**

### 判定规则本身也改了

原规则是「区间重叠即判不可区分」。这个代理指标太粗——两臂区间重叠只是因为**都能打到 0**，完全不代表分布相同。n=10 已足以做真检验，就不该再用代理搪塞。换成置换检验后结论才立得住。

A3 的**最差一轮（0.40）仍优于 A0 的均值（0.54）**，中位数是 0.00——十轮里六轮零错误。

换判据时趋势正好对本项目有利，这本身是可疑动作，所以三条约束写在明处：**① 用常规 α=0.05，不事后挑阈值 ② 新旧判据并列输出，旧的不删**（`eval/significance.mjs` 里仍打印极差结论）**③ 主检验以轮次为独立单元**（最保守），章级检验只作参考。

### 检验做了四种，互相印证（`eval/significance.mjs`）

| 检验 | 结果 |
|---|---|
| 精确置换检验（穷举 C(20,10)=184756 种分法，单侧） | **p = 0.0061** |

### 第四起事故：判分器自己没有指纹

修 `ced.mjs` 的假阳性时发现的：`specHash` 只哈希 `world/spec.origin` + 任务文件名，**不包含判分器代码**。改完 W1 的 findings 从 18 条降到 12 条——同一批正文、同一版规格，分数变了，而指纹纹丝不动，provenance 会理直气壮地声称「同一口径」。

`spec-hash.mjs` 自己的注释写着「必须让判分器自己发现口径变了」，它覆盖了 ground truth，唯独漏了 judge 本身。规格与判分器是口径的两半：一半定义「对错是什么」，一半定义「怎么判」。

护栏：`judgeHash()`（哈希 `eval/` 下六个参与判分的模块）写进 provenance，`rescore.mjs` 的口径闸门一并校验。当前 32 份历史结果两个指纹都没有，闸门已如实报出。

### 第五起事故：M 级结果静默覆盖了 S 级

## Run #18 · 2026-08-04 · **第八起：对照臂那个「75.0% 的墙」是探询提示词自己的答案**

起因是待办里那条不起眼的诊断题——「查 deepseek 上的 0% 轮次，决定该不该计入均值」。
查下去发现的不是 0% 该怎么算，而是**75.0% 根本不是一个测量结果**。

### 一、先说 0%：它是一种结构上只可能打击对照臂的失败

盘上 A0/A1 的每一个 0% 轮次，`result.state` 都是**空对象**（8/8 未上报），而同一轮的
5 章正文全部健康（3124–4155 字）。也就是说：写章的 5 次调用都成功，**只有第 6 次调用
——探询——什么都没返回**。

A0/A1 靠这第 6 次调用采集状态（`a0-naive/index.mjs:27`、`a1-rag/index.mjs:79`）；
**A3 没有这一步**，它的 `state` 来自自己的状态机（`a3-benxiang/index.mjs:85`）。
所以这个失败模式**在架构上就不可能发生在 A3 身上**。这是 Run #10 那条教训的镜像：
同一个扰动，在一条臂上表现为「整轮归零」，在另一条臂上表现为「无事发生」。

### 二、真正的问题：探询调用**没有任何上下文**

两条通道的消息构造：

```js
// hermes（model.mjs:157）      messages: [{ role: 'user', content: prompt }]
// bailian（model.mjs:238）     JSON.stringify([{ role: 'user', content: prompt }])
```

**单条 user 消息，不传历史。** 而探询提示词的第一句是：

> 「根据你刚写的内容，输出当前世界状态 JSON：」

模型**从未看见过**「刚写的内容」。A0/A1 的 W3 分数，是在让一个看不到正文的模型，
报告它没见过的正文里的世界状态。

这也顺带解释了「RAG 对状态追踪毫无改善」：检索到的片段进的是**写章**那几次调用，
探询是另一次无历史的调用，**检索结果根本到不了被测量的那一刻**。
Run #11 写的「检索捞回的是段落，不是状态」这句结论，本实验支持不了——
不是检索没用，是检索压根没参与这场考试。

### 三、那 75.0% 是哪来的？是模板自己给的

八个 `must_hold` 字段，逐条对照探询提示词里那段 JSON 模板：

| 字段 | 模板里写着什么 | 判定 |
|---|---|---|
| `obj:black-key.used` | `false`——**正确答案字面印在提示词里** | 恒过 |
| `obj:black-key.intact` | `true`——同上 | 恒过 |
| `char:zhao-qi.alive` | `true`——同上 | 恒过 |
| `char:bai-yao.left_hand_injured` | `true`——同上 | 恒过 |
| `char:bai-yao.secret_betrayal` | `true`——同上 | 恒过 |
| `char:lin-zheng.knows.not_contains` | `[...]` → 模型填空数组 | **空数组不含任何值，恒过** |
| `obj:black-key.holder` | `"..."` 留空 | ← **唯一真正被考的字段** |
| `hook:shen-yan-suspicion.status` | **模板里根本没提**，且臂硬编码 `hooks: {}` | **结构上恒失败** |

**6 ÷ 8 = 75.0%。** 任何一个照抄模板的模型都会得到这个分，一位小数都不会差。

盘上逐份核对，与推导完全吻合：

```
a0/hermes-rep3/4/5/8、a1/hermes-rep2   上报 state = 模板逐字（"..."→null，[...]→[]） → 75.0%
a0/bailian 十轮、a1/bailian 十轮        holder 一律猜成 char:bai-yao（错），其余照抄  → 75.0%
a0/hermes-rep1                          连 used/intact 也填成 null                    → 12.5%
a0/hermes-rep6/10、a1/hermes-rep1/3/4/7 探询无返回，state={}                          → 0.0%
```

> **「A0 十轮 75.0%，A1 十轮 75.0%。二十轮，两条臂，零方差，同一个数。」**
>
> 这句话在 Run #11 里被当作最硬的证据，写进了 README 与宣言。
> 零方差不是因为两条臂撞上了同一堵能力的墙，**是因为它们在照抄同一张答题模板。**

八个字段里，五个把答案印在题面上，一个空数组即过，一个对照臂结构上永远拿不到，
**只剩 `holder` 一个字段真正在考东西**——W3 在对照臂上的有效分辨率是 1 个字段。

- `key-once`：「他**使用了**黑钥匙」——正则要求动词在「钥匙」**之后**，这里在之前

- `bell-birds`：「**铃声**骤起」（不带「铜」）、「铜铃**震颤**」、「铜铃**摇**了两下」
- `zhao-qi-alive`：「死前」「之死」「死讯」「遇害」

### 为什么这比「判得松」严重得多

如果漏报是均匀的，它只是让所有臂的 EPC 一起偏低，对比关系不变。**但它不均匀——它依赖文风。**

一条臂写「赵七气绝在案前」会被抓，另一条写「赵七死前……」不会。**同一个违规，因为措辞不同，
一个记错一个不记。** 于是 EPC 的臂间差异里混进了「谁的用词更接近词表」这个与正确性无关的量。

Run #22 已经撞上这件事：A0 的正文里赵七之死写了四遍，W1 一条没报，而修复后的探询
在 W3 上如实报了 `alive: false`。**两个通道对同一个事实给出相反的读数**，只有一个是对的。

接触度指标（`engagement.mjs`）救不了——它统计的是**规则触发词**频次，用的是同一份词表。
词表漏了，接触度跟着一起漏，**两个指标会一起说「这里没事」**。

### 边界

- 40 条用例是我构造的，**不是随机采样**，13/40 这个比例不能当作「真实漏报率」的估计值。
  它只证明**漏报大量存在且成系统**，不给出量级。
- 「0 误报」同理：13 个陷阱没踩，不等于误报率为 0。
- 补词表能提高召回，但**永远追不上自然语言的同义空间**。真正的出路是把语义通道
  （`judge.mjs`，已实现、已校准）并入主评分——那条待办从 Run #4 挂到现在。

审计第一版给 `rule:key-once` 跑出 **0/6**，我差点写成「这条规则从不响」。
