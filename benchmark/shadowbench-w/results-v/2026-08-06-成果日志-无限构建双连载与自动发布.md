## 三、修复的四个真实 bug（都已固化）

1. **hermes 通道 config 解析正则 `\Z` 失效（最重要）**：JS 正则没有 `\Z`（Python 才有），
   `(?=^\S|\Z)` 中 `\Z` 被当字面 Z → 匹配永远失败 → **HTTP 主通道从未生效**，一直在走
   CLI 兜底（本机有 hermes.exe 所以长期未暴露）。GitHub Actions 上 `spawn hermes ENOENT`
   暴露。改为无 /m 的 `(?=^\S|$)`，HTTP 通道实测返回真实 token 用量。
   影响：所有 hermes 通道调用从此真正走 HTTP（长提示词无上限能力上线）。
2. **数值账本初始值公式错**：初始 5×5 属性 + 5 点未分配 = 30，公式误写 25+(level-1)×5
   → 初始即负债，ch1 反复被拒。修正为 30+(level-1)×5。
3. **文本禁区词表粒度**：计数类描述（「七个人」「超过六人」）被词表误伤——电梯公寓是
   「计数」主题，正文必然讨论人数。教训：文本禁区只适合动作词（扫码支付/按下按钮），
   不适合数量描述。词表收窄为明确违规动作（「挤了七」「按下负一层」）。
4. **GitHub Actions 环境**：gh secret set 经 stdin（--body -）写入的值无效（401），
   改直接传参；briefs 目录不存在导致 git add 失败，脚本加 mkdir -p。

## 四、自动发布流水线（无限构建的核心）

- rulekeeper（中文）：cron 每天 22:30 UTC（北京 06:30）
- the-zero-slot（英文）：cron 每天 22:45 UTC（北京 06:45）
- 流程：检测下一章号（outline 最大章+1，失败不落盘 → 天然幂等）→ clone 2origin 引擎
  → secrets 生成 config.yaml → 写章（五道门禁）→ 同步展示版 → git push
- **briefs 共创口子**：共创者 PR `briefs/chNN.md` 决定下一章剧情方向（无 brief 自由续写）
- 实测：rulekeeper ch07（1361 字）与 the-zero-slot ch07 均云端生成并推送成功
- 架构：引擎单点维护在 2origin，世界包（world/）在各自共创仓库，`git log` 即连载史
