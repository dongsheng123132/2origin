# ShadowBench-W · 写侧基准设计（v0.1 草案）

> **W = Write-side。** LoCoMo / LongMemEval / LifeBench / ConStory-Bench 全部只考核「读侧问答」或「成品质量」，不考核写回本身——AI 更新完世界状态后，那个状态是不是对的？违反约束有没有被拦住？证据链全不全？
>
> 原写「没人定义过的考题，定义者拿标准制定权」。**2026-08-03 复核后下调：写侧已有人进场（见 W3 行下方），长篇叙事域尚空，窗口按周计不按年计。**

## 一、三道考题（W1/W2/W3）

| 编号 | 名称 | 问什么 | 现有基准覆盖情况 |
|---|---|---|---|
| **W1** | 生成一致性 | 新写的内容违反了多少既定事实？ | ConStory-Bench 部分覆盖（但仅 8k–10k 词） |
| **W2** | 缺陷检出 | 已存在的矛盾能查出多少？（准确率/召回率） | 无（笔灵等商业产品有功能无公开评测） |
| **W3** | **状态回写正确性** | 写完之后，系统自己维护的世界状态对不对？ | 2026-07 起有人进场，长篇叙事域仍空（见下） |

W3 是关键。所有现有系统（mem0/Letta/Zep 到天命）都在写回状态，**而写回的状态是否正确，长期无人测量**。一个系统可以写出通顺的正文却把人物状态更新错，错误在 200 章后才爆发。W3 直接把这个盲区变成可测数字。

> **2026-08-03 修正——本文档原写「完全空白，这是我们的独有考题」，该说法已过期，不得再对外使用。**
>
> 2026 年 7 月最后两周出现两篇直接进入写侧的工作：
>
> | 论文 | 与本基准的关系 |
> |---|---|
> | **Ground Truth First**（arXiv 2607.21962，07-24） | **语料方法学撞车**：同样「先播种带 validity interval 的事实、再生成正文」，使 gold answer by construction。但它机械生成的是**问答**，评的仍是 QA 准确率；W3 评的是系统**自己写回的状态字段**。 |
> | **ConsistencyGate**（arXiv 2607.22962，07-25） | **门禁机制撞车**：写入前的 admission gate。但它用 K 次采样自洽软分数（随机），A3 用确定性规则校验器 + 带证据退回重写；域也不同（对话事实记忆 vs 叙事世界状态）。 |
>
> 剩余的差异化仍然成立，但比原先窄得多：**长篇叙事域 + 确定性规则门禁 + 评「写回的状态字段」而非问答**。
> 窗口也远短于 research/ 文档估计的 12–18 个月——两周内两篇。

## 二、语料方案：世界规格先行（顺带自证协议）

不用受版权保护的网文，也不用公版古典（文体不匹配）。**自建语料，CC0 发布**（与 docs/07 承诺一致）。

构建顺序刻意反过来——**先有世界状态，再生成正文**：

```text
① 人工/AI 编写世界规格（ground truth）
   人物 40+、地点、物品、势力、世界规则、时间线、伏笔计划
   每个状态带 valid_from 事件
              ↓
② 从规格生成基线正文（分卷/章/场景）
   生成时每章绑定「本章允许的状态变更」，保证正文与规格一致
              ↓
③ 校验：正文回读一遍，确认无规格外矛盾（人工抽检 + LLM 交叉）
              ↓
④ 派生两份语料：
   Clean 版（用于 W1/W3）
   Planted 版（注入 N 个已知矛盾，用于 W2）
```

三个好处：**ground truth 天然存在**（不必事后人工标注，省掉最大成本）；**注入矛盾的位置已知**，W2 的准确率/召回率可自动算；**构建过程本身就是本象协议的一次实证**（世界规格 = 本象，正文 = 投影）。

规模分级，逐级放行：

| 级别 | 基线正文 | 续写量 | 用途 |
|---|---|---|---|
| S | 3 万字 | 5 章 | Gate 0 生死题 |
| M | 20 万字 | 20 章 | 架构验证 |
| L | 100 万字 | 50 章 | **旗舰公开测试**（全球空白区） |

## 三、实验臂（同一模型，只变上下文供给与写回方式）

| 臂 | 方案 | 代表现状 |
|---|---|---|
| **A0** | 裸模型 + 尾部截断 | 最朴素基线（ConStory-Bench 显示它意外地强） |
| **A1** | 向量 RAG 检索 topK | 当前主流（Long-Novel-GPT 等） |
| **A2** | **纯提示词状态维护**：每章重写完整 JSON 状态，无校验/证据/上下文编译 | 决定性方法消融：分离「要求维护状态」本身的收益 |
| **A3** | **Benxiang**：状态机 + 语义事务 + 证据链 + 预算编译 | 本项目 |

控制变量：同一底模、同一世界规格、同一续写任务、同一随机种子策略；只变「上下文怎么给」和「状态怎么写回」。

## 四、指标

```text
CED          每万词一致性错误数（采用 ConStory-Bench 口径，便于横向对话）
违规拦截率    写回时被校验器挡下的真实违规 / 全部真实违规
误杀率        被挡下但其实合规的比例（防止「宁可错杀」刷分）
W2 准确率/召回率   注入矛盾的检出表现
W3 状态准确率  写完后系统状态与 ground truth 的字段级匹配率
证据可追溯率  状态字段能追溯到正确来源事件的比例（A3 独有维度）
Token / 成本 / 延迟
```

综合口径沿用 docs/06：

```text
有效效率 = 正确完成任务数 ÷ (Token 成本 × 延迟)
```

## 五、Gate 0：第一道生死题（必须先过）

**背景**：ConStory-Bench（*Lost in Stories*, arXiv 2603.05890，2026-03）实测发现，多步 agent 写作系统的一致性**反而显著差于顶级裸模型**。加结构不等于更好，做错了更差。

**规则**：在 S 级（3 万字 / 5 章）上，若 **A3 的 CED 高于 A0**，立即停止扩大规模，回头改架构。

不允许的辩解：「规模再大点就好了」「换个模型就好了」。先在小规模赢裸模型，才有资格谈百万字。

**这条 kill criteria 写在最前面，是为了让失败可见——本项目的诚实边界（docs/07 第六节）在基准上的体现。**

## 六、harness 结构（Phase 1 第一批代码）

```text
benchmark/shadowbench-w/
├── README.md              # 本文件
├── world/                 # 世界规格（ground truth，CC0）
│   ├── spec.origin/       #   直接用本象包格式——自证
│   └── planted.json       #   注入矛盾清单（W2 答案）
├── corpus/                # 生成的基线正文（CC0）
├── arms/                  # 四个实验臂的运行器
│   ├── a0-naive/
│   ├── a1-rag/
│   ├── a2-prompt-state/   #   纯提示词维护完整状态；无校验、证据与上下文编译
│   └── a3-benxiang/
├── eval/                  # 判分器
│   ├── ced.mjs            #   一致性错误检测（规则 + LLM-judge 双通道）
│   ├── state-diff.mjs     #   W3：系统状态 vs ground truth 字段级比对
│   └── report.mjs         #   汇总表 + 有效效率
└── results/               # 每次跑的原始记录（可复现，含 prompt 与响应存档）
```

判分原则：**能用规则判的绝不用 LLM 判**（状态字段比对、伏笔回收、时间线顺序都是确定性的）；只有「文意是否矛盾」这类才走 LLM-judge，且双模型交叉 + 分歧人工裁决。

## 七、成本粗估（S+M 级，四臂）

主要开销是语料生成与续写。S 级四臂一轮约几美元量级；M 级约几十美元；L 级（百万字语料生成 + 四臂各续写 50 章）预计低三位数美元。**先跑 S 级 Gate 0，通过再往上投。**

## 十、W3-V：视觉方言（2026-08-04 新增，装置已就位，尚未真跑）

起因是一个提议：把「AI 动漫角色一致性」做成第一个对外 Demo，因为视觉效果直观。

**这个提议按原样不成立**，理由是本基准自己的数据：角色脸漂是**表层一致性**问题，属 W1 类，
而 Run #11/#14 已在两个级别上独立证明 W1 不是本象的战场（S 级 p=0.9905，M 级 p=0.3361，
廉价向量 RAG 用更低 Token 打平）。更何况脸漂比 W1 还低一层——它是渲染器缺少稳定 identity
表示，靠视觉锚（参考图 / LoRA / ID embedding）解决，一份文字 schema 描述不到脸的分辨率。

但把诉求**收窄**之后，剩下一个真问题，而且它是 W3 形状的：

> 系统能不能从世界状态，投影出一份**属性正确、且跨镜头不掉**的分镜表？

不测像素，测属性。于是有了 W3-V：

| 类 | 判什么 | 为什么它是视觉方言独有的 |
|---|---|---|
| **V1 持有** | 黑钥匙的持有者值域、**单调性**、终局归属 | 道具在角色间来回瞬移，**任何单帧都看不出**，只有把镜头排成序列才判得出 |
| **V2 属性持续性** | 白遥 `left_hand_injured` 在其在场的**每一镜**都须为 true | 「第 1 秒女孩 A、第 10 秒女孩 B」的属性版——崩坏的可测代理 |
| **V3 规则的视觉后果** | 铃响须见禽鸟惊飞；门须闭；渡口镇持令牌须交械 | `rule:bell-birds` 的规格原文写着「可观测现象，**不可静默发生**」。正文里鸟飞是可选修辞，分镜表里不画就是漏了画面元素 |
| **V4 画面泄漏** | 林峥不得有识破白遥的**表演指示** | 禁区换了形态：正文里泄密是一句话，分镜里泄密是一条表演指示。正则通道，单列不并入主分 |

**主指标 EPS（每百镜错误数）**，次要指标**属性掉落率**。接触度下限（SPC / 白遥在场镜数 /
含钥匙镜数）不达标即标注「分数不可与达标轮次并列」——少画几个镜头刷零错误必须被看见，
这是 Run #10 的教训在视觉方言里的形态，而且更容易犯。

```bash
node eval/shot-selftest.mjs                              # 判分器自测（20/20 全绿）
node run-shot.mjs --provider stub                        # 零成本跑通
node run-shot.mjs --provider stub --scenario drifting    # 验证判分器抓得住崩坏
```

**三条设计约束，都是前七起事故换来的：**

1. **考题不放进 `world/spec.origin/`**。`specHash()` 递归遍历该目录，往里加文件会当场改掉
   规格指纹——而 A3 的 deepseek 臂此刻正在跑，provenance 已写死 `530fa01ad056`。
   那正是第二起事故的形状：纯新增、`git diff --stat` 人畜无害、指纹却变了。
   代价是 `specHash` 遍历不到它，所以 `shotTaskHash()` 单独把考题内容入指纹。
2. **判分器自带指纹**（`shotJudgeHash()`）。第四起事故：`specHash` 覆盖 ground truth 却漏了
   判分器本身，改完否定过滤 findings 从 18 降到 12，指纹纹丝不动。
3. **上下文供给一行不 fork**。A1 直接 import `retriever.mjs`，A3 直接 import
   `compileContext`，三臂**共用逐字相同的输出指令**——否则 W3-V 的差异里会混进提问方式的差异。

**自测第一跑就抓到判分器自己的洞**：`「铜铃未响」`的否定词落在正则**匹配区间之内**
（铜铃**未**响），而我只查了匹配之前的 6 个字。与 ced.mjs 第四起同型——否定词插在主语与
谓语之间，前缀窗口永远够不着。修完补了反向陷阱用例（「不停地响」是程度副词不是否定）。

### 边界（必须与任何结果一并说明）

> **这道题只测投影，不测渲染。跑赢它不等于生成的视频不崩。**
> 它证明的是链条上游的一环：状态能否正确编译成一份可渲染的画面规格。
> 下游渲染器认不认这份规格、认了之后画面稳不稳，本基准不作任何声称。

**尚未真跑**——A3 的 deepseek 臂跑完前不占用配额。真跑前还差：A3 是否接写回门禁
（画面违规退回重画）须单独立项并单独计成本，现状是**只投影、无事务**。
