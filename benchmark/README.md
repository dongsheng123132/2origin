# benchmark/ · ShadowBench（Phase 1 首要任务）

> 协议成立与否由这里的数据决定，不由文档决定。MVP 决策依赖本目录的实验结果（见 [docs/06-路线图](../docs/06-路线图与MVP候选.md) 第二节）。

## 对比的三种输入方式

1. **纯文本**：原始文字 / Markdown 全量或截断
2. **普通截图**：PDF 页图或屏幕截图
3. **本象包**：atlas（视觉总览+对象编号）+ graph（对象关系）+ exact（按需精确载荷）

## 指标定义

| 指标 | 定义 |
|---|---|
| 理解准确率 | 任务答案与标准答案的匹配率 |
| 输入 Token | 实际计费的输入 token（按各模型官方计法，视觉 token 单独记录） |
| 响应时间 | 请求发出到完整响应的墙钟时间 |
| API 成本 | 按官方价格折算的实际成本 |
| 对象定位成功率 | AI 引用的对象 ID/路径能正确解析回真实对象的比例 |
| 修改成功率 | 提交的事务通过校验并正确落地的比例 |
| 验证成功率 | 修改后通过全部约束验证的比例 |
| 错误与幻觉率 | 答案中无中生有内容的比例（人工评审） |

**综合指标：**

```text
有效效率 = 正确完成任务数 ÷ (Token 成本 × 延迟)
```

## 首批任务（草案）

- [ ] 找出 100 页 PPT 中的重复页
- [ ] 找出 PPT 中文字与图表数据矛盾
- [ ] 找出 Excel 中影响利润的公式依赖链
- [ ] 中断会话后恢复项目状态（Memory 方言）
- [ ] 50 万字文本上续写一场戏，统计设定违反数（Story 方言）
- [ ] 找出网页截图中对应的可操作对象

## 决策规则

只有当本象包**明显**优于纯文本和普通截图（有效效率领先，且定位/验证成功率显著更高），对应 MVP 路径才立项。如果不明显，修正协议假设——这个信息比选对 MVP 更有价值。

测试数据全部自行生成，CC0 发布，保证可复现。
