# CAD 对象级审计“10×”预注册验证协议

状态：`preregistered / not yet executed`  
目标：验证本象对象级证据链是否在一个明确、可重复的审查任务上达到 10×，而不是泛称“整体比 CAD 软件或大模型好 10 倍”。

## 1. 主张边界

本实验只检验两项可能的 10×优势：

1. **争议对象复核时间**：审查员收到“这个窗是否被错算”的异议后，从开始查找到给出可定位证据所需的时间。
2. **修订版重审时间**：图纸发生一轮局部修改后，完成受影响对象重查并更新审计包所需的时间。

不检验、也不允许由本实验推出：

- 本象比 ODA File Converter 或 LibreDWG 更会解析 DWG；
- 本象已经能代替美国 AHJ、建筑师或专业工程师做法规签署；
- 本象对任意 CAD 格式、任意天正版本或任意美国辖区都达到同样结果；
- 当前中山案例已经证明了 10×。

## 2. 数据集

- `CN-01`：当前受控复杂 DWG 脱敏案例；只在授权的本机环境使用原件，公开包只保留 SHA-256 和脱敏证据。
- `US-01`：公开的美国建筑平面图集，含门窗表或可由两名审查员建立对象级真值。
- `US-02`：公开的美国联邦/公共工程 CAD 或 BIM 图集，符合 NCS/A/E/C CAD 习惯。
- `US-03`：公开的美国许可申请 PDF 图集，至少包含一次修订版。

US 数据必须覆盖至少两种输入链：`DWG/DXF` 与 `PDF`；有条件时加入 `IFC/Revit export`。规则开发与最终盲测图集分离。

## 3. 对照组

| 组别 | 工作方式 | 允许工具 |
|---|---|---|
| A | 人工 CAD/PDF + Excel 计数与复核 | 常用查看器、标注、表格 |
| B | 通用多模态大模型 | 渲染页/截图、普通提示词，不提供本象对象图 |
| C | 解析器/脚本“只报总数” | ODA/LibreDWG/自写脚本，输出总数或实体列表 |
| D | 本象对象级审计 | 稳定对象 ID、位置锚点、`why/history/limits`、审计投影 |

ODA 和 LibreDWG 是 D 组可用的底层转换/解析组件，不作为“本象的敌人”。比较的是审查工作流，不是库的品牌。

## 4. 任务

1. 给出窗、门和未分类对象数量。
2. 对随机抽取的 30 个对象逐个回答：是否计入、位于哪里、依据是什么。
3. 注入 10 个争议项，要求审查员复核并形成可交付证据。
4. 对修订图重复审查，只报告新增、删除、分类变化和受影响统计。
5. 生成客户可读报告，并列出不能保证的部分。

## 5. 指标

- 对象级 precision / recall / F1；
- 总数绝对误差；
- 关键漏项率；
- 单个争议对象复核时间的中位数与 P90；
- 修订版重审总时间；
- 证据覆盖率：有稳定 ID、来源位置、分类依据、历史和能力边界的结论比例；
- 重复运行稳定性：对象 ID 与计数是否保持一致；
- 数据外传：处理期间是否发生非必要网络上传。

## 6. “10×”通过门槛

只有同时满足以下条件，宣传材料才可写“在对象争议复核上达到 10×”：

- D 组争议复核时间中位数不超过最佳合格对照组的 `1/10`；
- D 组对象级 F1 `>= 0.98`，且不低于最佳对照组超过 1 个百分点；
- 关键漏项率为 0；
- 证据覆盖率 `>= 95%`；
- 至少 3 份美国图集均达到门槛，而不是只在当前单一样本上达到；
- 公开原始计时、错误清单、环境版本、输入哈希和失败样本。

修订版重审的 10×主张独立判定，不得用它替代争议复核指标。

## 7. 真值与盲测

- 两名独立审查员分别建立对象级真值，分歧由第三人裁决；
- 计时人员不知道系统预期结论；
- 随机对象和争议项在实验前锁定并保存哈希；
- 任何在盲测后改过的规则都必须重跑全套，并标记为新版本；
- 失败图纸进入报告，不从数据集中静默删除。

## 8. 当前基线

当前受控案例已证明：`194 = 4 + 190`，模型空间中 `190 = 168 窗 + 22 门 + 0 未分类`，位置锚点覆盖 `190/190`。当前没有人工计时、盲标真值和竞争工作流的同图运行记录，因此速度倍数为 `N/A`，不得写成 10×结果。
