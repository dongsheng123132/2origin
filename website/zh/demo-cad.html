2Origin / 案例 / CAD 版本对比

图纸改了一版，机器怎么知道哪根梁被挪了

下面对比的两份 DXF 是仓库里公开的真实 fixture C-101.dxf / C-101-v2.dxf——不是合成数据。解析用的是与命令行 node adapters/cad/import.mjs 完全同一段代码（parseDxf + dxfToObjects），对比逻辑照抄 adapters/cad/diff.mjs。全部在你的浏览器里现算，没有后端。

这两份图纸是 AC1015（R13 以上），图元带真正的实体句柄，所以"同一根梁"在两版之间靠句柄识别，挪动了也认得出来——不会被误判成"删了一根、加了一根"。如果换成没有句柄的 R12 图纸（案例墙上的 A-101/B-201 就是），版本对比会退化成纯粹的几何内容比对，见下方"不能推出"。

01 · 差异可视化

C-101 → C-101-v2

底图是新版（C-101-v2）的实际坐标（单位 mm），按真实 bbox 画出每个图元；虚线红框是旧版里存在、新版里已经删除的图元，叠加在它原本的位置上。鼠标悬停查看对象 ID 与坐标。

02 · 逐条差异

field-level diff

不能推出

  • 版本对比依赖稳定对象 ID。这两份 fixture 是 R13+ DXF、带真实实体句柄，ID 才能稳定跨版本对齐；如果换成 R12（无句柄）图纸，几何一变 ID 就变，对比会退化成"删了一个、加了一个"——不是 bug，是格式本身的限制，导入器会如实标记 id_basis:"content"，本页两份 fixture 均无此标记。
  • 对比只覆盖机器能提取的字段（图层、坐标、长度、编号），不理解设计意图——B03 变宽了 500mm 是设计升级还是画错了，机器不判断，只报"变了"。
  • 这不是工程审图、签章或合规工具，案例墙上的窗洞审计案例范围同样有限，均不能替代人工审图。
  • 本页面完全在浏览器本地计算，不接收上传；两份 fixture 原文件在 GitHub ↗，可用 node website/zh/demo-cad/verify.mjs 交叉核对本页计算结果与命令行 adapters/cad/diff.mjs 的输出是否一致。
