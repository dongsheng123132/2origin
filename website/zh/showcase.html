案例 01 · 当前可用 Beta

可复核教材预检与受限结构副本

这是第一条完整能力链。它不是“自动优化教材”，也不把任何结果称为最终交付。真实 DOCX 仅在本机 U-King 工作台处理；本站只展示合成回放的流程和边界。

本机可用公开页：合成回放交付门：不可用
  1. 输入授权 DOCX 只进入本机；公开页不上传、不保存文件。
  2. 观察ZIP/DOCX 安全闸门、只读观察、教材判据与 findings。
  3. 建议确定性审阅候选；每条绑定来源、判据与位置，不代替人工判断。
  4. 人工选择本机操作者可标记已阅、暂缓或拒绝；这不是签名或审批。
  5. 受限副本仅唯一定位的缺失标题可生成新副本，插入“【待编辑补充】”；不改原件与正文。
  6. 复检复核输出副本与记录链；仍不代表内容正确、排版正确或可交付。

公开演示的边界

  • 不上传客户 DOCX、不展示原文、绝对路径、身份或其他案例。
  • “完整性自检”只相对于当前副本与记录链头；不等于签名、存证或不可篡改。
  • 本页不虚构多 Agent 实时协作——没有真实案例时，只显示"尚未开始"。已发生过的多 Agent 协作留痕回放见 AgentTeams。

Speech · Experimental

语音与方言

只作为观察实验方向。尚未形成足以公开承诺准确率的方言识别能力。

Vision · Experimental

视觉与视频

把观察结果接入对象状态的方向；不把演示页面称为视频理解产品。

Human-in-the-loop

人始终在链上

人可以看状态、改选择、拒绝建议；系统必须记录边界，而不是替人伪造结论。

无界面动作包

给工作台调用，不给网页假装万能

本象协议自身与三个方言 skill（小说写作、状态持久化、原生文档结构化）已在 ClawHub / SkillHub 上架、可一条命令装走；多 Agent 协同的发证与身份闸门以 AgentTeams 为协同基点，是本方案的核心 Skill；跨机跨人的任务交接已开源并发布到 npm。全部都保持本机优先、只读观察与可复核的边界，不把审阅建议或协同结果伪装成自动交付。

book-docx-safe-preflight

输入：本机 DOCX。输出：安全预检、只读观察与教材判据 JSON。默认不写回，不上传。

ClawHub 公开 Beta
book-review-package

输入：已验证的本机案例。输出：复核来源哈希与记录链后的 advisory-only 审阅包。

ClawHub 公开 Beta
certify.stamp / observe / certify / whoami

输入：状态路径 + 经验 id，身份由 observeIdentity() 观察得到，不从参数取。输出：certify.result JSON，状态里记 exam.examiner 与 separation_strength，写发证台账。以 AgentTeams（原名 Hiclaw）自带 Matrix homeserver 为协同基点，作者不能给自己发证。

AgentTeams 桥接 · 判据 50/50 + 真 Tuwunel 12/12
task-passport

输入：任务短号。输出：.taskpack（ZIP + BagIt，RFC 8493）或 JSON，让任务带着当前世界状态跨 harness、跨机、跨人接力，不搬运聊天记录。

MIT · GitHub + npm task-passport@0.3.0
origin-writer

输入：章节草稿与状态包。输出：每章一笔语义事务，过五道门禁（禁区/伏笔状态机/正文对照/自报断言复核）才落盘。站内可现场试用同一案例包 novels/月落渡口.origin/ 的真实回放，见本象小说。
