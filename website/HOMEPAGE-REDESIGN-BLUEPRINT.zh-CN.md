# 本象官网首页改版蓝图（中文主稿）

> 文档性质：产品与内容蓝图，不包含 HTML/CSS/JS 修改
>
> 适用页面：`website/all-in-one.html#home`
>
> 核心受众：决赛评委、技术合作者、愿意亲手验证的早期采用者
>
> 首屏目标：30 秒看懂，90 秒验证，3 分钟开始行动

## 1. 改版结论

首页不应继续以“理念宣言 + 一组漂亮数字”为主线，而应回答四个连续问题：

1. 本象解决什么根本问题？
2. 一次 AI 写入到底怎样被验证？
3. 哪些能力现在已经能跑，证据等级是什么？
4. 访客下一步如何亲手验证？

保留当前黑、白、金的视觉系统和“影子 → 本象”叙事，但重排信息结构：**产品定义 → 真实交互 → 核心能力 → 可运行范围 → 证据边界 → 快速开始**。

首页所有数字必须来自单一数据源；实验结果、协议测试、合成样例、真实文件和生产验证必须明确分级，不能混写。

## 2. 版本范围与原则

### 2.1 本轮保留

- 黑色首屏、纸张式浅色内容区、金色强调色。
- 中文主叙事与英文镜像能力。
- “聊天是窗口，世界状态应持久存在”的核心观点。
- 法律、CAD、XLSX、项目记忆、长篇写作等已存在案例资产。

### 2.2 本轮调整

- 首屏从“抽象宣言”切换为“一句话产品定义 + 可验证承诺”。
- 用一次完整事务演示解释本象，而不是让访客先读架构术语。
- 用证据等级替代未经限定的“已完成”“已验证”。
- 将 CLI、MCP、Skills、Office、Writer 纳入能力地图。
- 将陈旧实验数字、长期运行页和案例细节从主导航降级。

### 2.3 本轮禁止

- 不使用“全球首个”“最难”“彻底解决”等缺少外部证据的表述。
- 不把合成 fixture 写成真实客户案例。
- 不把协议测试通过写成生产可用。
- 不在首屏继续使用旧的 Run #27 数字作为核心证明。
- 不把 Python 实现描述为完整兼容。
- 不手工维护多个相互独立的统计数字。

## 3. 全局导航

### 3.1 主导航文案

`首页｜90 秒演示｜能力与证据｜案例｜白鼓挑战｜GitHub`

### 3.2 次级入口

以下内容不再占用主导航，放入页尾或对应章节：

- 法律演示：归入“案例”。
- 长期运行：证据未刷新前只在“诚实状态”中展示。

### 3.3 行为要求

- 当前章节使用 `aria-current="page"` 或等价语义。
- 中英文切换使用真实按钮，并暴露 `aria-pressed`。
- 桌面端保持单行导航；移动端使用抽屉，或提供明确的横向滚动提示。
- 所有可点击区域不小于 44 × 44 px。

### 屏 3：90 秒核心演示

**标题**

> 一次变更，六步交代清楚。

**说明**

> 下面不是动画概念图，而是一笔可重放的项目决策事务。

**演示对象**

> `decision:release-scope` 当前状态为 `proposed`，当前世界水位为 `seq 42`。

**六个交互页签**

1. 当前状态
2. 候选事务
3. 门禁结果
4. 已提交状态
5. Why 证据链
6. 并发冲突

**步骤一：当前状态**

```text
object: decision:release-scope
status: proposed
owner: agent:planner
seq: 42
```

**步骤二：第一次候选事务**

```text
intent: 将发布范围从 proposed 改为 decided
missing: rationale
```

**步骤三：门禁拒绝**

> 事务已退回：`decision:release-scope.rationale` 必填。原状态未改变，seq 水位保持 42。

界面必须同时显示“候选事务”和“已提交状态”，避免再次出现“提示拒绝，但对象树已改变”的矛盾。

**步骤四：补全理由并提交**

```text
rationale: 首版仅保留协议内核、CLI 与可复现实验；生产适配器不进入本次发布。
```

> 提交成功：seq 43–45。责任者 `agent:planner`。改动已进入 append-only 证据链。

**步骤五：Why 证据链**

```text
current value  decided
changed by     agent:planner
transaction    tx:release-scope-0043
source         PROJECT_BRIEF.md#release-boundary
validated by   decision-rationale-required
sequence       43–45
```

**步骤六：并发冲突**

> 写入冲突：事务基于 seq 42，当前世界已到 seq 45。请重新读取状态后再提交。

**演示声明**

> 演示仅在浏览器本地运行，不上传数据；候选事务与已提交状态分栏显示。

### 屏 4：核心能力

**标题**

> 本象不是更大的 JSON，而是持久的对象层。

**能力一：持久世界状态**

> 对象、关系、约束、状态和边界保存在 `.origin` 包中，不依赖某一次聊天上下文。

**能力二：语义事务**

> AI 提交对象级变更，不直接覆盖最终文件；每次变更都带意图、责任者和依据。

**能力三：确定性门禁**

> 规则由确定性编译器执行。门禁不通过，原状态不动；通过后才生成新的事实。

**能力四：Why 证据链**

> 从当前字段回到事务、来源、责任者和规则，不靠模型事后编故事。

**能力五：并发冲突保护**

> 基于旧世界状态提交的事务会被拒绝，避免多个 Agent 静默覆盖彼此结果。

**能力六：边界进入状态**

> 未实现能力、适用范围和限制与对象一起保存，让“不能做什么”也成为可查询事实。

### 屏 7：案例

**标题**

> 问题、命令、证据，三件事说清楚。

每个案例卡片固定使用四行结构：`问题 / 本象动作 / 返回证据 / 证据等级`。

**项目记忆**

- 问题：新会话只能重新阅读大量上下文，关键决策容易丢失。
- 本象动作：通过 MCP 读取项目状态、提交语义事务、查询历史和诊断包。
- 返回证据：对象当前值、事务序列、责任者、来源与限制。
- 证据等级：`E2E SELFTEST`。
- 按钮：查看 Shadow Memory。

**Office 文档**

- 问题：DOCX / PPTX 转成纯文本后，章节、表格、勾选框和结构关系容易丢失。
- 本象动作：解析原生结构，生成对象与关系，保存结构哈希并复核转换结果。
- 返回证据：章节、条目、表格、勾选框、结构哈希和验证结果。
- 证据等级：`REAL FILE` + `SELFTEST`，分别展示。
- 按钮：查看转换证据。

**CAD**

- 问题：几何特征被修改后，很难说明修改意图、约束和责任者。
- 本象动作：把零件、特征、关系和约束映射为可提交对象。
- 返回证据：候选事务、门禁结果、提交序列和 Why 链。
- 证据等级：`SYNTHETIC FIXTURE`。
- 按钮：查看 CAD 方言。

**法律**

- 问题：条款修改可能与义务、比例或上位规则冲突。
- 本象动作：以条款和规则对象运行确定性门禁，拒绝不满足约束的候选事务。
- 返回证据：冲突规则、原状态、候选状态和拒绝理由。
- 证据等级：`SYNTHETIC FIXTURE`。
- 按钮：查看法律演示。

**XLSX**

- 问题：表格中的数值、公式和来源被复制后，语义与依据分离。
- 本象动作：把工作簿结构、字段语义和来源关系放入可验证对象层。
- 返回证据：单元格语义、来源关系、变更事务和限制。
- 证据等级：`SYNTHETIC FIXTURE`。
- 按钮：查看 XLSX 方言。

### 屏 9：诚实状态

**标题**

> 我们不主张什么。

**引导语**

> 本象当前最重要的产品能力，是让结果可验证；这不等于所有效果指标已经证明。

**当前结论**

- 在现有实验中，提示词显式状态相对基础提示提升 41.3 个百分点，差异显著。
- 在提示词显式状态之上加入完整本象机制，提升 2.5 个百分点；当前实验不足以证明这一增量显著。
- 当前能够保留的类别性结论是：提示词方法不产生持久证据链；本象实验中的证据覆盖率为 15.0% / 27.5%，提示词组为 0%。

**明确不主张**

- 不主张已经证明节省 token。
- 不主张已经证明提高行文一致性。
- 不主张已有生产适配器、真实用户规模或生产 SLA。
- 不主张 Python 实现已经完整兼容。
- 不把合成 fixture 当成真实业务验证。
- 不把 selftest 独有覆盖包装成完整协议覆盖。

**按钮**

- 阅读完整实验结果
- 阅读撤回与限制

## 6. 视觉与交互规范

### 6.1 视觉语言

- 继续使用黑色舞台、浅色纸张、金色关键状态。
- 标题可保留宋体 / 高对比衬线气质，正文与代码使用清晰的无衬线 / 等宽字体。
- 金色只用于“已提交事实、关键行动、当前状态”，红色只用于门禁失败或冲突。
- 不新增图库式 AI 大脑、机器人或无关 3D 装饰；核心视觉应来自真实对象、事务、门禁和证据链。

### 6.2 布局

- 正文最大宽度统一为 1080 px。
- 首屏桌面端采用 5:4 双栏；移动端按“定义 → 按钮 → 事务卡 → 证据条”顺序串行。
- 能力卡桌面端 3 × 2，移动端单列。
- 证据表和终端内容必须放在可滚动容器中，不能撑破页面。
- 动效只用于说明状态变化：候选 → 拒绝或候选 → 提交；尊重 `prefers-reduced-motion`。

### 6.3 移动端硬规则

- 390 px 视口不得出现页面级横向滚动。
- 所有 Grid / Flex 子项设置可收缩边界，如 `min-width: 0`。
- 表格、代码块和证据链在自身容器内滚动。
- 长对象 ID 可换行或中段省略，但复制时保留完整值。
- 导航、语言开关和主要 CTA 的点击目标不小于 44 px。

## 7. 数据与证据架构

建议新增一个由验证脚本生成的状态文件，例如：

```text
website/data/project-status.json
```

建议字段：

```json
{
  "generated_at": "ISO-8601 timestamp",
  "commit": "git sha",
  "verify": { "status": "PASS|FAIL|STALE", "ran_at": "timestamp" },
  "conformance": { "javascript": "87/87", "python": "60/79", "unimplemented": 19 },
  "mutation": { "caught": "19/19", "selftest_only_gaps": 2 },
  "challenge": {
    "totals": { "chapters_verified": 0, "words": 0 },
    "latest": { "transaction_id": "", "verified_at": "" }
  }
}
```

约束：

- 文件由仓库命令生成，首页只消费，不允许设计稿或 HTML 手填关键数字。
- 每个证据数字都链接到生成来源。
- 超过约定刷新周期时显示 `STALE`，不能继续展示为当前结果。
- 中英文页面读取同一数据源，只翻译标签，不复制数字。

## 10. 首页成功判断

新版首页通过的标准不是“更漂亮”，而是第一次访问的人能够准确复述：

> 本象把 AI 对项目的修改变成可验证的语义事务；门禁失败时不写入，成功后每个字段都有证据链。当前协议和多个方言已有可运行证据，但真实生产适配与部分跨语言实现仍在建设中。

如果访客只能记住“这是一个宏大的 AI 理念项目”，而说不清事务、门禁、Why 和当前证据边界，这次改版就没有完成。
