# 2Origin all-in-one 前端整体审阅

审阅对象：`http://localhost:8765/all-in-one.html#home`

审阅日期：2026-09-02

## 结论

页面已经很好地展示了“影子 / 本象 / Origin IR / 语义事务”这套核心概念，桌面端视觉风格统一，案例、挑战、法律 Demo、长期任务也形成了较完整的信息架构。但它还不适合直接作为当前项目的对外总览：第一屏和证据区使用了已经被 README 后续实验收窄的旧主张，协议向量、Python 实现和白鼓进度也存在旧数字；同时缺少 npm CLI、`why` 证据链、并发冲突、四个可安装 Skill 和 AgentTeams 交付面的介绍。手机端存在可复现的横向溢出。

## 最高优先级问题

1. 事实口径过期：页面仍以 Run #27 的 95.8% 对比作为第一屏主证据；当前 README 的最终口径是 A0→A2 +41.3pt，而 A2→A3 只有 +2.5pt 且不显著，唯一幸存的分类性主张是提示词无法产生证据链。
2. 协议数字过期：页面写 68/68、Python 60/60；当前仓库是 JS 87/87、Python 60/79 且 19 项未实现，变异 19/19。
3. 法律 Demo 的“零写入”展示自相矛盾：拒绝后文案说原状态不变，但对象树同步显示 `ratio -0.55`；同时露出 `55.00000000000001%` 浮点脏值。
4. 手机端失败：390px 视口下首页文档宽 613px，解决方案页宽 444px；流程图、卡片和表格把页面撑出视口，导航也需要横向滚动且没有明确提示。
5. 当前能力覆盖不完整：页面没有突出 npm CLI、90 秒真实终端演示、`why` / `limits`、并发冲突、四个 Skill、Office 当前实现与 AgentTeams 交付验证面。
6. 状态可信度受损：首页白鼓进度仍是 2+4 章，而挑战页已经显示 16 章 / 81,589 字符；长期任务数据停在 2026-08-07，且显示 `no run yet`。

## 已做得好的部分

- 一句话定位和视觉隐喻有记忆点，Origin IR 七要素与编译流程解释完整。
- 案例页按“问题 / 可跑命令 / 证据”组织，方向正确。
- 法律 Demo 的合规与拒绝交互可运行，并有 `aria-live`；页面抽样无控制台 error / warning。
- 中英文首页切换完整，桌面端视觉层级、排版和焦点样式较好。
- 当前仓库 `npm run verify` 本次实跑退出码为 0，说明底层能力比页面展示更强。

## 审阅步骤

1. 首页（桌面）：视觉健康；核心证据口径高风险。
2. 宣言：叙事清楚；部分成熟度描述与当前仓库不一致。
3. 解决方案：能力矩阵清楚；缺少成熟度、证据级别和限制标签。
4. 案例：可运行路径清楚；fixture、自测、真实数据、生产验证未分级。
5. 白鼓挑战：规则和进度可理解；旧基准与“全球第一”表述风险高。
6. 法律 Demo：主交互可运行；拒绝状态的对象树和百分比显示不可信。
7. 长期任务：页面可读；当前数据陈旧且没有成功运行证据。
8. 英文首页：翻译和布局基本完整。
9. 手机端：首页和解决方案页均出现横向溢出，不通过。

## 证据限制

- 审阅开始时工作区正被另一个本地流程更新；截图前它已完成拉取并提交 `website/all-in-one.html`。审阅结束时当前页面对应本地提交 `3ae562f`，本地 `main` 比 `origin/main` 超前 1 个提交。
- 本轮验证了页面呈现、主要导航、语言切换、法律 Demo、移动端重排和本地 `npm run verify`，没有核验所有外链、真实用户数据、生产部署或完整 WCAG 合规。
