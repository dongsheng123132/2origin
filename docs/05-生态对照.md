# 05 · 生态对照：借鉴谁，不重复造谁

> 战略总纲：**不重新实现每一种文件格式，不与成熟项目正面重复；把它们作为 Adapter，重点建设统一协议、证据系统、差异系统和验收标准。**

## 一、直接接入为 Adapter 的项目

### OfficeCLI（iOfficeAI/OfficeCLI）——Office 方言的执行底座

已经在做「AI First Office」：AI 原生 CLI + JSON 输出、稳定路径定位（`/slide[1]/shape[2]`）、读写 Word/Excel/PPT、HTML/PNG 渲染、文档校验、MCP 接入、「render → look → fix」闭环，且不依赖安装 Microsoft Office。

**结论：不要从头再造。** 作为 `adapters/office` 的执行底座，在其上补充多渲染器比对、证据追溯和统一报告。

### Docling（docling-project/docling）——语义层

把多种文档转为统一的 `DoclingDocument`：文本/表格/图片、文档层级、页面布局、Bounding Box 坐标、Provenance、多格式输出、MCP 服务。正是「语义投影」——回答「这段文字原来在第几页、什么坐标、来自哪个对象」。不是高保真渲染器，与 OfficeCLI 互补。

### MarkItDown（microsoft/markitdown）——低成本兜底

多格式转 Markdown、明确供 LLM 消费。官方自认不适合高保真视觉转换。只用作低成本的 `extract_text() / summarize() / search()`，**不作为验收渲染器**。

### Flint（microsoft/flint-chart）——关键先行证明 + 图表方言

**这是对本象协议最重要的外部验证。** Flint 不是「把文字压成图片」，而是让 AI 输出紧凑的语义意图（字段语义 + 图表意图），由确定性编译器生成完整的 Vega-Lite/ECharts/Chart.js/Plotly/原生 Excel 图表。70+ 语义类型；微软测试中三个模型上的评审分数均高于直接生成完整配置。

对应关系（Flint 是本象在图表领域的方言）：

| Flint | 本体系 |
|---|---|
| 原始数据 | 本象载荷 |
| `semantic_types` | 本象语义 |
| `chart_spec` | 投影意图 |
| Flint Compiler | Shadow Runtime |
| 多后端输出 | 不同影子 |
| Warning/Validation | 叠象验证 |

Flint 的 Agent Skill 规则「不要重新输出大型数据集，只引用字段名，让宿主绑定真实数据」= 本象事务的核心原则。MIT 许可，提供 TS/JS 库和 MCP Server，直接以依赖方式接 `adapters/flint-chart`。**注意：只对接其公开输入输出接口，不依赖内部结构**（项目仍在快速迭代，Python 版尚为预览）。

## 二、方向已被验证的同路项目

### CLI-Anything（HKUDS/CLI-Anything）

「把给人用的软件转成 Agent 可调用的结构化 CLI」：覆盖 FreeCAD、Blender、GIMP、Inkscape、Draw.io，强调 JSON 输出、Preview、Trajectory、命令与渲染结果关联、真实软件渲染。证明了「不是让 AI 模拟鼠标用旧软件，而是给旧软件加 Agent-Native 外壳」。CAD 阶段的重要接入对象。

### Modulor（bcllcc/modulor）

AI 原生 CAD 内核：无传统 GUI、JSON 输入、CLI/MCP/Python API、参数化模型、内置 measure/validate/render-and-see 闭环。还早期，概念上与「AI First CAD」高度一致，持续跟踪。

### kkFileView（kekingcn/kkFileView）

最接近传统「万能文件预览器」：Office/WPS/PDF/OFD/CAD/3D/压缩包/音视频/邮件等。本质是给人看的在线预览器（Office 依赖 LibreOffice）。**借鉴**它的文件类型路由、转换缓存、适配器体系、格式覆盖清单、超时与任务队列；**不以**它的 Web 预览 UI 为核心。

### WrenAI（Canner/WrenAI）——AI 协议的上手机制参考

数据/BI 领域的 GenBI 引擎（Apache-2.0，17k star）：语义层（MDL）+ 受治理的 text-to-SQL + AI 上下文层 + MCP。**不是本象同类格式协议，不抄它的 SQL 引擎/仪表盘/22 连接器/商业版 RLS 分层**；它的价值在两处——**本象「语义是可版本化工程资产」的方向被 17k star 独立验证**，外加一个真正可抄的上手机制：

| WrenAI 做法 | 本象对应/可借鉴 |
|---|---|
| **Discovery stub**（~50 行）：`npx skills add Canner/WrenAI` 自动识别 Claude Code/Cursor/Cline/Codex，装一个引导文件，教 agent 按需 `wren skills get <name>` 拉工作流，**content always matches installed version** | **第三方采用机制的答案。** conformance §五的断点是「两份实现出自同一作者，要等真正的第三方」；stub 让第三方 agent 不用读整本规范——装个引导文件就能按需取「当前版本」的工作流，版本钉住防止文档落后于实现 |
| **`wren ask --guided | --direct`**：对弱/强 agent 包装同一个问题（guided 展开、direct 透传） | 对应 `profiles/*.yaml` + 上下文编译器，补「按 agent 能力重写任务」这一层 |
| **MDL**：业务含义写成 Git 友好、可审查、可 diff 的文件，且同一份定义同时驱动执行 | 印证 `graph/ + semantics + constraints` 方向（本象已做，作为论文/对外先例引用） |
| MCP server 作为 OSS 开放面 | 印证本象 MCP 规划（compiler/mcp.mjs） |

## 三、记忆与长上下文方向

| 项目/研究 | 关键点 | 与本象的关系 |
|---|---|---|
| **GraphRAG**（microsoft） | 实体关系 + 社区分层摘要 + 按需检索，处理大语料局部/全局问题 | 证明图结构优于全文塞入；本象在其上加：精确原文、可修改对象、当前状态、事务、验证 |
| **Letta** | archival memory：长期信息存在可检索外部记忆，不常驻提示词 | 同方向；本象进一步管理对象/关系/状态/证据的一致性，不只是「记住信息」 |
| **Anthropic 上下文工程** | 外部记忆、压缩、清除已处理工具结果 | 与「本象持久化、上下文只做临时投影」一致 |
| **Lost in the Middle**（论文） | 模型对长上下文中间区域利用弱于两端 | 「无限扩窗不是答案」的理论依据 |

## 四、格式与来源标准（参考，不重造）

| 标准 | 借鉴什么 |
|---|---|
| **OpenUSD** | 时间采样、分层组合（Layer/LIVRPS）、引用、多来源组成一个场景——最接近「本象」理念的现有格式 |
| **JSON-LD** | 用 JSON 表达带上下文和关系的关联数据，跨系统对象互认 → `graph/` 关系层 |
| **Apache Arrow** | 类型化列式数据、零拷贝交换 → 大型结构化载荷 |
| **HDF5** | 大型、异构、层次化数据组织 → 科学数据载荷 |
| **OCI Image Spec** | manifest + 配置 + 可独立寻址分层 → `.origin` 包的包装思路 |
| **PROV-O**（W3C） | 实体、活动、来源关系的标准表达 → `provenance/` |
| **C2PA** | 清单、修改声明、内容哈希记录来源与编辑过程 → 证据链 |
| **Jupyter nbformat** | 同一文件保存文字+代码+富媒体输出+元数据的小规模先例 |

## 五、视觉压缩研究（能与不能）

| 研究 | 结论 | 对本象的启示 |
|---|---|---|
| **DeepSeek-OCR** | 文字:视觉 Token <10x 时 OCR 精度 ~97%，20x 时降至 ~60% | 视觉压缩有效但有硬边界 |
| **VTCBench** | 能读回压缩文字 ≠ 长距离检索/关联推理/长期记忆也行 | 图只负责「找」，不负责「懂」和「准」 |
| **Set-of-Mark**（microsoft/SoM） | 图片上覆盖可引用的编号标记，显著改善视觉定位 | atlas 层的对象编号方案直接采用 |
| 各模型视觉 Token 计费差异 | Claude 1000×1000 ≈ 1296 token；Gemini ≤384×384 = 258 token，大图分块 | 投影必须按目标模型 profile 适配（`profiles/*.yaml`） |

**警示**：「把文字塞进图片」很快会成为模型厂商自己的功能。护城河不在这里，而在：可寻址的多维上下文、任务自适应编译、可执行（影核）、可验证（叠象）、跨格式统一动作面。
