# 02 · 概念体系（全项目术语准绳）

> 本文档是所有文档、代码、对外表述的术语基准。新增术语必须先在这里登记。

|---|---|---|---|

体系分工口诀：

> **影域负责隔离，本象负责保存，叠象负责看见与比较，影核负责行动，舟舱负责人类确认，影刻负责复制扩散。**

## 二、一源万影（One Origin, Many Shadows）

核心理念的展开是四个「一」：

### 1. One Semantic Core, Many Surface Shadows（一个语义核心，多个界面投影）

同一个 Excel 操作，可以通过 Excel GUI、LibreOffice、Python、OfficeCLI、WPS、Web Office 完成。界面都是影子，语义核心只有一个。

### 2. One Artifact, Many Projections（一个对象，多种投影）

同一个本象可以拥有：文字视图、数学视图、数据视图、几何视图、时间视图、因果视图、视觉视图、交互视图。

### 3. One Action, Many Executors（一个动作，多个执行器）

`replace_text` 可以由原生 Office、OOXML 直接修改、LibreOffice、OfficeCLI、GUI 自动化分别执行。影核协议负责路由与回退。

### 4. One Result, Many Verifiers（一个结果，多重验证）

同一个结果经过文件结构验证、原生软件打开验证、视觉验证、语义验证、AI 交叉验证、用户确认。叠象负责汇总为可信度结果——给 AI 的不是一张 PNG，而是一个带证据的结论。

## 三、六步工作闭环

```text
Observe → Understand → Act → Render → Verify → Commit
 看见   →   理解    → 行动 →  呈现  →  验证  →  提交
```

对应组件流转：

```text
叠象感知 → 影子对象模型 → 影核动作协议 → 真实软件执行
       → 叠象重新渲染与比较 → 舟舱人工确认 → 提交真实文件
```

## 四、本象的一个具象例子

一个 PPT 文件进入系统后，生成多个影子：

```text
原始 PPTX
   ↓
结构影子：幻灯片、形状、文字、图片
语义影子：标题、结论、数据关系
视觉影子：每页截图、总览图
动作影子：允许执行的修改动作
版本影子：修改前后差异
证据影子：真实 Office 打开的结果
```

AI 先在影子世界里：看见 → 理解 → 模拟修改 → 预测影响 → 执行 → 重渲染 → 检查差异，最后才提交到真实文件。

## 五、三层上下文结构（投影的标准形态）

给 AI 的上下文不是纯图片也不是纯 JSON，而是三层：

| 层 | 内容 | 职责 |
|---|---|---|
| **视觉总览** atlas | 页面缩略图、时间轴、关系图、热力图、对象编号、风险标记 | **图负责找**：极少 Token 获得全局认识 |
| **结构本象** graph | 对象、关系、依赖、可用动作（带稳定 ID） | **结构负责懂**：不必从图片里猜对象 |
| **精确载荷** exact | 原始文字、公式、参数、原图、代码、条款 | **原文负责准**：需要时才取 |

口诀：

> **图负责全局，结构负责关系，原文负责精确，影核负责执行，叠象负责证明。**

## 六、三套协议的边界（不要都塞进影核）

| 协议 | 归属 | 负责 |
|---|---|---|
| **Artifact Projection Protocol**（投影协议） | 本象/叠象 | 文件结构、语义、坐标、预览、可用动作、来源追踪 |
| **ActionParity Protocol**（影核协议） | 影核 | 动作定义、参数、前置条件、执行器选择、失败回退、撤销 |
| **Evidence Commit Protocol**（证据提交协议） | 叠象 | 多渲染器验证、差异报告、风险评分、人工审批、证据链、最终提交 |

三者合称 **Shadow Runtime Protocol / 影子运行时协议**。

## 七、反面清单（这些说法是错的）

为防概念漂移，明确以下表述**不成立**：

- ❌「本象 = 把文字截图成图片省 Token」——图片压缩只是投影技术之一，不是存储方式
- ❌「本象 = 一个更大的万能 JSON / 万能 DOM」——Office/CAD/ZIP 本质不同，只共享生命周期（inspect/render/query/act/diff/validate/commit/rollback），不共享数据结构；通用外壳 + 领域方言，否则只会做出最低公分母
- ❌「本象 = 支持 500 种格式的预览器」——那是传统软件打法
- ❌「本象能把 100 万字无损压缩成几千 Token」——它管理上下文限制（像操作系统管理内存），不消灭上下文限制
- ❌「摘要可以代替原文」——摘要是可重建投影，无权覆盖本源事实；推断与事实必须分离标注
