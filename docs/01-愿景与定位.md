# 01 · 愿景与定位

## 一、起点：一个渲染器报错暴露的基础设施缺口

这个项目的直接起因非常具体：AI 生成了 Office 文件，本机却没有可用的渲染器打开验证。

但往下挖一层，问题不是「缺一个渲染器」，而是——

> AI 已经能生成 Word、Excel、PPT、CAD 等真实文件，却没有一套稳定的**「打开-看见-定位-修改-复验」**系统。

再往下挖，是三个结构性缺陷（详见 README）：**感知**（AI 没有眼睛）、**记忆**（上下文必炸）、**输出**（终态不稳）。三者共享同一个病根：

> **我们把「投影」当成了「对象本身」。**

## 二、人类的信息史：一部不断压扁世界的历史

人类为了适应纸张、屏幕、语言和带宽，把真实对象一轮轮压扁：

```text
真实建筑 → CAD模型 → 平面图 → PDF → 截图 → OCR文字
真实企业 → 业务流程 → Excel表 → 汇总数字 → 一段报告
真实思想 → 关系网络 → 文章结构 → 线性文字
真实运动 → 时空过程 → 视频 → 抽帧 → 图片描述
```

越往下越容易传播，丢失的信息也越多。AI 现在大量读取的，正是这种多轮压缩后的「影子的影子」。

**文字并不落后**——它是人类发明的极高压缩率、低带宽、强组合的表示方式，数学符号同理。问题不在使用文字，而在**把文字投影误当成对象本身**：

- 对法律条款，文字可能就是最核心的本源层
- 对 CAD，几何和约束才是本源，文字描述只是投影
- 对 Excel，公式和数据依赖才是本源，屏幕像素不是
- 对软件，代码、状态和运行行为才是本源，截图不是

所以本象协议不是「反文字」，而是**多表示、可切换、可追溯**。

## 三、关键技术边界：投影不可逆

从三维模型生成二维图片是容易的；但仅从二维图片恢复唯一的三维模型，通常不可能——无数不同的三维对象可以产生相同的二维投影。

```text
三维模型 → 二维投影   ✅ 容易
二维投影 ⇏ 唯一三维本体 ❌ 不可逆
```

因此「还原本源」不能靠事后从 PDF/文字/图片里猜回来，唯一可靠的路径是：

> **始终保留本源对象、投影规则和修改历史。**

这就像数据库：人看到的是报表，系统真正保存的是数据、关系和查询逻辑。未来的文档也应该这样——PDF、图片、Markdown 都只是本象生成的缓存视图。

## 四、定位：不做万能渲染器，做 AI 时代的中间表示层

「支持 500 种文件预览」是传统软件的打法。本象协议的定位高一层：

> **让 AI 能够可靠地看见、理解、修改和验证任何数字生成物。**

计算机体系的精确类比：

```text
传统编译体系                  本体系
──────────────               ──────────────
高级语言                      Word / CAD / Excel / 视频 / 网页 / 对话
    ↓                            ↓
中间表示 IR          ←→       本象 IR（Origin IR）
    ↓                            ↓
机器指令             ←→       影核动作（Action Kernel）
    ↓                            ↓
不同硬件执行         ←→       Office / CAD / CLI / GUI / Agent 执行器
                                 ↓
                              PDF / 图片 / 文字 / 三维 / 界面投影
```

| 组件 | 类比 | 职责 |
|---|---|---|
| 本象 IR | LLVM IR | 数字对象的持久语义与状态 |
| 影核协议 | 统一指令集 | 一个动作，多个执行器 |
| Shadow Runtime | 虚拟机 | 加载、计算、投影、运行本象 |
| 叠象 | 调试器 + 测试 + Git | 差异、验证、证据、版本 |
| 确认台 | 显示器 + 控制台 | 面向人的投影与确认 |

## 五、两条已被外部验证的判断

**判断一：AI 最稳定的输出，不是最终成品，而是受约束的中间表示。**

Microsoft Flint（flint-chart）已在图表领域证明：让 AI 直接输出几百行 Vega-Lite 配置又脆又错；改为输出紧凑的语义规格（字段语义 + 图表意图），由确定性编译器补全细节，质量和稳定性都更好。「AI 负责表达意图，编译器负责完成细节」——Flint 就是本象协议在图表领域的一个方言（详见 [05-生态对照](05-生态对照.md)）。

**判断二：未来不是让 AI 模拟鼠标使用旧软件，而是给旧软件增加 Agent-Native 外壳。**

CLI-Anything、OfficeCLI、Modulor 等项目都在把「给人用的软件」转换成「Agent 可调用的结构化接口」。本象协议不与它们竞争，而是站在它们之上做统一协议、证据系统、差异系统和验收标准。

## 六、AI 的工作方式将如何改变

传统 Agent 只覆盖「理解 → 行动」，缺失可靠感知、真实渲染、结果验证、证据留存、安全提交。完整闭环应该是六步：

```text
Observe → Understand → Act → Render → Verify → Commit
 看见   →   理解    → 行动 →  呈现  →  验证  →  提交
```

AI 不直接操作现实文件，而是先操作它的「影子」——就像软件开发的「源码 → 编译 → 测试 → 提交」，数字工作也应该是：

```text
生成物 → 投影 → 修改 → 验证 → 提交
```

对话也一样：**Chat 只是操作本象的一个临时窗口，不再是项目本身。** 即使关掉对话、切换模型、上下文清空，项目仍然完整存在。

## 七、最高层宣言

> 过去的软件把数字世界展示给人。
> 本象协议把数字世界展示给 AI。
>
> AI 不再盲目点击界面，也不再修改文件后靠猜测结果。
> 它能够看见对象、理解结构、执行动作、比较变化，
> 并用证据证明工作已经完成。

一句话总结：

> **人类用文件保存信息，AI 时代用本象保存世界状态。**
