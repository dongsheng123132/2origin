# 00 · 极简核心（CORE）

> **如果只读一页，读这一页。**
> 本页是整系协议（本象 / 影核 / 本境）的骨架——用 [引用优先](09-引用优先-Reference-First.md)
> 递归地校验它们自己。其余所有文档都是本页的展开、方言、或证明。
>
> 🌍 **[English](00-CORE.en.md)**

## 一句话

**对象有一个稳定 ID 指向唯一真源；任何人只拿引用、用时解析、解析验版本；AI 只交付事务、由校验器落地；承诺只保证可核对的部分。**

## 五个概念（整个系统就这些）

| # | 概念 | 是什么 | 它回答 |
|---|---|---|---|
| 1 | **对象** | 稳定 ID + 唯一真源 | 这是什么？谁是真的？ |
| 2 | **引用** | 极小 · 稳定 · 可解析 · 新鲜（版本/水位/指纹） | 我拿的是地址还是副本？ |
| 3 | **投影** | 按需生成、可重建、注明丢弃；永不真源 | 这个视图能代表原物吗？ |
| 4 | **事务** | AI 的输出 = 引用什么 + 断言什么 + 改什么 | AI 怎么安全写回世界？ |
| 5 | **校验** | 可核对即承诺；未钉死如实标注 | 这句话算不算数？ |

## 三协议 = 这 5 个概念 + 方言

| 协议 | 它的"对象" | 方言（可选扩展，不进核心） |
|---|---|---|
| **本象** | `.origin` 包 / 对象 ID | Story · Office · CAD · Chart · Memory … |
| **影核** | 动作名 | 每个执行器是它的方言 |
| **本境** | 环境指纹 | detector · rule · adapter 是它的方言 |

## 表面复杂度审计（核心之外都是什么）

| 层 | 是 | 必需？ |
|---|---|---|
| 核心 | 上面 5 个概念 | ✅ 必需 |
| 方言 | 各领域自己的 Schema | 按需，永远不进核心 |
| 证明 | 一致性向量、mutation、证据链 | 承诺越多越必需，可增长 |
| 约定/文档 | 术语、目录布局、动作面、README | ⚠️ 真正可精简的臃肿所在 |

例子：统一动作面 9 个动作，**真核只有 3 个**——`inspect`（读）、`commit`（写）、`validate`（查）；
`render / project / query / act / diff / rollback` 都是它们派生的。核心之外皆可选。

## 方言自检表（新方言立项先填这一页）

**填不出任何一行 = 概念没想清，别立项。** 5 个概念之外的"真新概念"才需要进核心评审；
方言只需把 5 个概念各说一句，说清了就进方言区。

| 概念 | 这个方言的"它"是什么 | 例子（Story 方言） |
|---|---|---|
| **对象** | 被引用的东西（稳定 ID + 真源） | 人物 / 物件 / 地点（`char:bai-yao`） |
| **引用** | 别人拿什么代替真值 | 对象 ID + 状态版本（`@state-822`） |
| **投影** | 按需生成、可重建的视图 | 三层上下文 atlas / graph / exact |
| **事务** | AI 写回世界的最小单元 | 语义事务（`append_scene` + `state_changes`） |
| **校验** | 可核对的承诺 | 约束谓词（`equals` / `unchanged`）+ 一致性向量 |

## 一条硬规矩（对协议的引用优先自检）

> **新方言 / 新协议若不能用这 5 个概念说清，就是在偷偷变大。**
> 先问：它引入的是**新概念**，还是**新方言**？新概念 → 进核心要过评审；新方言 → 不进核心，随意。
